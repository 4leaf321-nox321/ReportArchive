# ReportArchive 보고서

`reportarchive` MCP 서버로 사내 보고서를 다룬다. 도구가 **40개가 넘는다.**

## 시작하기 전에 — `get_guide()` 를 먼저 부른다

```
mcp__reportarchive__get_guide()
```

무엇을 어떤 순서로 써야 하는지, 각 절차의 주의사항이 거기 있다. **서버가 최신본을
쥐고 있으므로** 이 파일이 오래돼도 안내는 항상 최신이다.

- 인자 없이 부르면 **"하려는 일 → 어떤 도구" 표 + 기본 습관**이 온다. 대개 이걸로 충분하다.
- 세부가 필요하면 그때 주제를 지정한다 —
  `write`(새로 쓰기) · `find`(찾기) · `edit`(고치기) · `comments`(댓글 반영) ·
  `publish`(게시) · `check`(자기 점검) · `composites`(종합보고).
- 한 번에 다 받지 마라. 필요한 주제만 받는 게 싸다.

## 이 파일에 내용을 더 적지 마라

예전엔 절차·형식이 전부 여기 있었다. 그런데 이 파일은 **각자 PC 에 복사된 사본**이라,
서버를 올려도 갱신되지 않는다. 실제로 도구가 27→43개로 늘고 안내가 162줄 바뀐 릴리스에서
복사하지 않은 사람에겐 아무것도 전달되지 않았다. 그래서 본문을 서버로 옮겼다.

내용을 고쳐야 하면 **저장소의 `mcp_server/guide/GUIDE.md`** 를 고친다. 그러면 모두에게
즉시 반영된다(각자 다시 복사할 필요 없음).

## 최소 원칙 (가이드를 못 받았을 때만)

`get_guide()` 가 실패하면 이것만 지키고, 사용자에게 가이드를 못 받았다고 알린다.

- **이름을 모르면 먼저 목록을 부른다** — 게시판·폴더·템플릿. 추측하지 않는다.
- **되돌리기 어려운 일은 미리보기부터** — 큰 수정은 `dry_run`, 게시는 `preview_publish`.
- **본문을 통째로 읽지 않는다** — 구조만 필요하면 `get_report_outline`, 표 한 줄이면 행 단위 도구.
- **생성물은 초안.** 발행(finalize)은 사람이 한다. 게시는 확인받고 2단계로.
