문서 중심에서
객체 중심으로

팔란티어의 핵심은 화려한 UI가 아니라 온톨로지다 — 세상을 객체·속성·링크로 모델링하고 모든 데이터를 그 위에 얹는 것. ReportArchive도 축을 뒤집었다: “문서가 중심, 객체는 태그”가 아니라 “객체가 중심, 문서는 그 객체에 붙은 증거 하나”. 이 문서는 RAG·온톨로지·지능화가 무엇인지 쉽게 풀고, 파운드리 대비 어디까지 왔는지를 한눈에 보여준다.

완료 — 모델·뷰·검색·AI·데이터 유입 진행 중 — 능동성(경보 Phase D) 예정 — 운동성(조치 Phase E)·구조화·AGE
01 / 기초 개념

온톨로지란 무엇인가

팔란티어(Foundry·Gotham)는 세상을 딱 세 가지로 모델링한다. 이 세 조각 위에 모든 것이 올라간다.

Object · 객체

현실의 실체

부품·시험·과제·실패모드·사람·조직처럼 “실제로 존재하는 것”. 문서가 아니라 대상 그 자체.

과제 “B300 방수설계” · 공급사 · 시험실행 · 실패사례
Property · 속성

타입 있는 필드

객체가 가진 값. 자유 텍스트가 아니라 연도·상태·수치처럼 타입이 정의된 데이터.

02 / 개념 사전

지능화의 용어들 — 쉽게

“RAG·GraphRAG·에이전트” 같은 말이 실제로 무엇을 뜻하는지, 그리고 우리는 그걸 어떻게 구현했는지.

RAG (검색증강생성)

완료

질문을 받으면 먼저 관련 문단을 찾아 오고, 그 근거를 읽은 뒤 LLM이 출처를 인용해 답한다. LLM 혼자 지어내지 않게 하는 방식.

아카이브 Q&A POST /ai/ask · 근거 청크 검색 → 번호 출처 → 인용 파싱

임베딩 · 벡터검색

완료

글을 “의미 좌표(벡터)”로 바꿔 저장한다. 단어가 안 겹쳐도 뜻이 비슷한 문서를 찾을 수 있다.

pgvector · bge-m3 1024차원 · HNSW 코사인 인덱스 (운영 Ollama :11435)

하이브리드 검색

완료

의미(벡터)와 글자(키워드)를 둘 다 써서 각 강점을 합친다. 오탈자·고유명사엔 키워드, 개념엔 벡터.

벡터 KNN + pg_trgm 키워드를 RRF로 융합 · 권한 밖 미노출

GraphRAG

완료

질문에서 씨앗 객체를 찾고, 온톨로지 링크로 이웃 객체까지 넓힌 뒤, 그 연결 근거를 일반 검색과 섞어 답한다.

질문→씨앗→expand_related 이웃→그래프 근거를 벡터검색과 블렌드 · 신규 테이블 0

온톨로지 에이전트

완료

LLM이 스스로 도구를 여러 번 호출하며 다단계로 조사한다. “객체 찾기→관계 넓히기→본문 검색→집계”를 엮는 팔란티어 AIP식.

도구 5종 tool-calling: list_object_types · search_objects · get_object · search_reports · aggregate_reports

재랭킹 · HyDE

완료

1차로 넉넉히 뽑은 뒤 LLM이 진짜 답이 되는 순서로 다시 정렬(재랭킹). HyDE는 “이상적 가상 답변”을 만들어 질문-문서 어휘 격차를 메운다.

qa._rerank(pool ×3) · qa._hyde · 설정 토글 + mock/장애 시 폴백

집계 라우팅 ★

완료

“2025년 낙하시험 실패한 과제 몇 개?” 같은 질문은 문단을 긁는 게 아니라 온톨로지 SQL로 정확히 센다. 파운드리다운 차별점.

structured_qa · 개수는 SQL 계산(환각 없음) · group-by/compare · 가시성 게이팅

근거 검증 · 평가

완료

답변의 각 주장이 출처에 실제로 있는지 대조(faithfulness). 그리고 골든셋·👍/👎로 검색 품질을 측정해 감 튜닝을 끝낸다.

qa._verify · eval.py(recall@k·MRR) · qa_feedback 테이블 + 골든셋 승격

데이터 채우기 (커넥터)

완료

벌크/붙여넣기 + REST·OData 커넥터 · 주기 스케줄러 · AI 자동매핑 · 계보 태깅

경보 · 트리거 (Phase D)

진행 중

일부러 만들지 않는 것 — 파운드리엔 있으나 우리 목표엔 과잉

완제품(목적특화)과 범용 데이터 플랫폼의 차이. 대등을 노릴 필요가 없다.

  • 데이터 파이프라인·변환 (Pipeline Builder / Code Repositories / Spark transform) — 우리는 동기화(sync)까지. 파생 데이터셋 변환 층은 불필요.
  • 분산 스케일·컴퓨트 (Spark, 페타바이트) — 단일 Postgres로 충분. 대규모 그래프만 D-3(AGE)로 대비.
  • 범용 앱 빌더 (Workshop / Slate — 남이 온톨로지 위에 앱을 짓는 층) — 우리는 완제품이다.
