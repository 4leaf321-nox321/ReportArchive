# 약점 보강 로드맵 — 협업 · Integration · 데이터베이스 view

ReportArchive 위젯 라인업(33개)을 Notion / Confluence 같은 상용 협업 플랫폼과
비교했을 때 드러나는 세 가지 약점 영역에 대한 단계별 개발 제안.

시각화 위젯은 이미 상용 SaaS 평균을 크게 상회하므로 추가 시각화 투자의 한계
효용은 작음 — **앞으로의 투자 우선순위는 협업 · integration · (선택적) DB view**.

---

## 1. 협업 / Inline 기능

보고서는 본질적으로 "리뷰 받는 산출물"이라 이 영역의 ROI가 가장 큼.

### 우선순위 1: 블록 단위 인라인 코멘트 ⭐⭐⭐
- 각 위젯(block) 옆에 thread 모양 핀
- thread당 여러 reply, resolve/reopen 상태
- `block.id` ↔ `comment_thread.id` 연결 (block 삭제 시 orphan 처리)
- 코멘트 모드 토글 (작성 모드 vs 리뷰 모드 분리)
- **구현 부담**: 중간. backend `comment` 테이블 + frontend floating thread UI. 1~2주.

### 우선순위 2: 멘션 + 알림
- `@사용자` 인라인 토큰 (rich_text 안에)
- 멘션 시 in-app + 이메일 알림
- 코멘트 안에서 멘션이 가장 자연스러운 진입점
- **구현 부담**: 중간. tiptap mention extension 활용 가능 (이미 tiptap 사용 중).

### 우선순위 3: 권한 분리 + 공유 링크
- viewer / commenter / editor 3단계
- 외부 공유용 read-only 링크 (token 기반)
- 페이지/보고서 단위 권한
- **구현 부담**: 중간. backend RBAC 확장.

### 우선순위 4: 변경 이력 / Diff view
- 보고서 버전 스냅샷
- "이 위젯의 이전 버전" 보기 + 복원
- "누가 / 무엇을 / 언제" 메타데이터
- **구현 부담**: 중간. 스냅샷 저장 + diff 알고리즘.

### 우선순위 5: 실시간 동시 편집 (CRDT)
- yjs + tiptap collaboration extension 도입 + 위젯 content sync
- **구현 부담**: 매우 큼 (1~2개월)
- **단기 대안**: 편집 lock (한 명만 편집, 나머지는 read-only) — 80%의 가치를 20% 비용으로

### 우선순위 6: 동기화 블록 (Sync Block)
- 한 위젯 content를 여러 보고서에서 공유, 한 곳 수정 시 모두 반영
- 회사 KPI, 공통 정의, 분기 일정 등에 유용
- backend `block.content` 외부 참조 모델 필요
- **구현 부담**: 중간~큼.

## 2. Integration (외부 서비스 임베드)

현재 `html_embed` 하나에 모든 임베드가 몰려 있어 시각적·UX 격차가 큼.
**가장 빠르게 격차 좁힐 수 있는 영역**.

### 우선순위 1: 이름 있는 임베드 위젯 ⭐⭐⭐

자주 쓰는 서비스 5~7개를 별도 위젯화. 각 위젯이 100~200줄, 7개 다 만들어도 1~2주.

| 위젯 | 핵심 가치 |
|---|---|
| `figma` | Figma URL → 디자인 미리보기 임베드 |
| `google_slides` / `google_sheets` | URL → 임베드 + 자동 미리보기 |
| `youtube` / `loom` | URL → 비디오 thumbnail + 임베드 |
| `code_sandbox` | URL → 라이브 코드 임베드 |
| `link_card` | 어떤 URL이든 OGP 메타로 미리보기 카드 |

**구현 부담**: 작음. URL 파싱 + iframe + OGP fetch.

### 우선순위 2: 데이터 소스 임베드 (차트 라이브 연결)
- Google Sheets URL → chart 위젯의 data source로
- CSV/JSON URL → 자동 fetch + 갱신
- 외부 데이터 변경 시 보고서 차트도 갱신
- **구현 부담**: 중간. backend fetch + cache + refresh 인프라.

### 우선순위 3: 이슈 트래커 위젯 (GitHub / Jira / Linear)
- PR/Issue 상태 라이브 표시 (open/closed/merged, assignee, labels)
- 보고서에서 진행 상황 추적
- API key는 organization 수준 보관
- **구현 부담**: 중간. 서비스별 API 클라이언트 + 인증 보관.

### 우선순위 4: 보고서 발행/공유 채널
- 완성된 보고서를 Slack 채널에 미리보기 카드로 발행
- 이메일 발송 (PDF + summary)
- Notion / Confluence에 export (한 방향 sync)
- **구현 부담**: 중간. 채널별 webhook 통합.

### 우선순위 5: 일반화된 OAuth + 통합 카탈로그
- Slack, Google, GitHub, Atlassian OAuth flow를 한 군데에서 관리
- 통합 추가 → 토큰 안전 보관 → 위젯에서 호출
- 미래의 모든 integration의 기반
- **구현 부담**: 큼. 초기 인프라 작업이라 6개 이상 통합이 쌓여야 ROI.

## 3. 데이터베이스 view 패러다임

작업 규모가 다른 두 영역과 차원이 다름. 보고서 플랫폼의 정체성에 영향.
**도입 전 큰 방향 결정 필수**.

### Phase 1: Dataset 엔티티 (필수 기반)
- 새 entity: `Dataset` — schema(columns: name, type) + rows
- 보고서와 독립적으로 존재 (페이지 트리 외부)
- CRUD UI: spreadsheet 같은 표 편집기
- **작업 규모**: 큼 (2~4주). 새 데이터 모델 + 권한 + UI.

### Phase 2: View 위젯 ⭐
- 보고서에서 dataset을 임베드하는 위젯 `dataset_view`
- 첫 view: **Table view** (필터/정렬/숨김 컬럼)
- 위젯 props에 `dataset_id` + `view_config` (filter, sort, columns) 저장
- **작업 규모**: 중간 (1~2주). 단일 view 우선.

### Phase 3: Multi-view (Notion DB의 핵심)
- 같은 dataset을 **Board (Kanban) / Gallery / Calendar / Timeline / Chart** 등으로 다시 보기
- 각 view는 다른 보고서에서 임베드 가능 (한 데이터, 여러 시각)
- view configs를 dataset에 저장 또는 위젯 props에 인라인
- **작업 규모**: 매우 큼 (2~4개월). 각 view 타입이 사실상 작은 위젯 하나.

### Phase 4: 외부 데이터 소스 연결
- Google Sheets / Airtable / Postgres / BigQuery 등을 dataset의 source로
- 자동 갱신 스케줄 + 캐싱
- **작업 규모**: 매우 큼. integration 우선순위 2·5와 합쳐서 진행.

### ⚠️ 도입 전 결정해야 할 핵심 질문

Notion DB 패러다임 도입은 **보고서 플랫폼의 정체성 결정**:

- **A. 그대로 보고서 툴로 유지** — dataset은 over-engineering. 기존 위젯들이 이미 데이터를 직접 들고 있고, 보고서는 "한 번 작성하고 발행" 모델
- **B. 워크스페이스 툴로 확장** — dataset이 핵심. 데이터를 한 곳에 두고 여러 보고서에서 참조하는 모델. 큰 방향 전환

B로 가면 별도 결정 과정이 필요.

## 권장 로드맵 (현실적인 6개월 플랜)

| 분기 | 핵심 작업 | 주요 효과 |
|---|---|---|
| **Q1 (1~2개월)** | 인라인 코멘트 + 이름 있는 임베드 위젯 5개 | 협업·통합 격차의 60%를 빠르게 메움 |
| **Q2 (1~2개월)** | 멘션 + 알림 + 권한/공유 링크 + 변경 이력 | "혼자 쓰는 도구"에서 "팀 도구"로 전환 완료 |
| **Q3 (1~2개월)** | 편집 lock + 동시 편집 indicator + GitHub/Jira 위젯 + Slack 발행 | 실무 워크플로 완전 통합 |
| **선택지 A** | CRDT 실시간 동시 편집 도입 | Notion/Docs 수준 협업 (매우 큰 작업) |
| **선택지 B** | Dataset + Table view + Board view | Notion DB 패러다임 진입 (방향 전환) |

### 핵심 한 줄

> **인라인 코멘트와 이름 있는 임베드 위젯 7개부터 시작.** 1~2주 안에 가시적 효과,
> 다른 모든 작업의 기반(특히 협업 워크플로 가설 검증).
>
> **Dataset/View 패러다임은 마지막에**, 그것도 "워크스페이스 툴로 확장"이라는
> 큰 방향 결정 후에.
