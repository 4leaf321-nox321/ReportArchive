## 0. 한 줄 요약

MCP 도구는 27개로 **찾기·읽기·쓰기·온톨로지·파일**까지 섰다. 남은 공백은 기능 목록이
아니라 **"AI가 사람처럼 일하려면 있어야 하는데 없는 것"** 이다 — ① 되돌릴 수단 ②
사람과 주고받을 통로 ③ 한 줄만 고치는 능력 ④ 자기 결과물을 확인할 눈.
**새 엔진은 만들지 않는다. 네 갈래 모두 백엔드 API가 이미 있고, MCP 노출과 얇은
어댑터가 대부분이다.**

---

## 1. 왜 지금인가 — 오늘 생긴 비대칭

Phase 6(2026-08-21)에서 **게시된 글도 AI가 고칠 수 있게** 열었다. 운영 기준 살아있는
보고서의 76%가 게시 상태이므로, AI의 수정 사정거리가 23% → 100% 로 넓어졌다.

그런데 **되돌릴 수단은 주지 않았다.** 버전 이력은 쌓이지만 MCP 에 목록·복원 도구가
없어, AI 가 잘못 고치면 사람이 웹에 들어가 복구해야 한다. 게다가 `report_versions.source`
는 `save|restore|publish` 뿐이라 **AI 가 고친 건지 사람이 고친 건지 구분도 안 된다.**

⇒ **권한을 넓혔으면 안전망이 먼저다.** 이 로드맵이 Phase A 를 안전망으로 시작하는 이유.

## 2. 설계 원칙

- **재사용 우선** — 신규 백엔드 엔진 0. 댓글·알림·버전·종합보고 API 는 **전부 이미 있다**.
  MCP 는 호출만 하고, 스마트 로직이 필요하면 백엔드에 얇은 전용 엔드포인트를 둔다
  (`/api/reports/browse` 가 그 선례).
- **사용자 권한 그대로** — MCP 는 호출자의 토큰을 전달한다. 새 도구도 만능 토큰을 만들지
  않는다. 댓글·알림은 그 사용자가 볼 수 있는 것만 보인다.
- **모르면 멈춘다** — 이름을 못 풀거나 대상이 모호하면 **조용히 넓히지 말고 에러**.
  (Phase 6 의 board/folder 이름 해석 원칙과 동일 — 조건이 빠진 전체 결과를 그 조직 것으로
  오해하는 사고를 막는다.)
- **토큰 예산 의식** — 도구 반환은 모델 입력 토큰을 먹는다. 열거는 요약 필드,
  본문 왕복은 최소화(Phase C 의 존재 이유), 큰 바이트는 out-of-band.
- **파괴적 동작엔 미리보기** — 되돌리기 어려운 조작은 `dry_run` 을 먼저 제공한다.

## Phase A — 안전망 (권한을 넓혔으니 먼저)

> 목표: AI 가 잘못 고쳐도 **AI 스스로 되돌릴 수 있고**, 나중에 **누가 고쳤는지 추적**된다.

- [x] **`list_versions(report_id, limit)`** — `GET /api/reports/{id}/versions` 노출.
      반환: `[{version_id, revision, created_at, author, source, size}]`. 백엔드 작업 0.
- [x] **`restore_version(report_id, version_id)`** — `POST .../versions/{vid}/restore` 노출.
      복원도 새 버전을 남기므로(source='restore') 되돌리기의 되돌리기도 된다.
- [x] **감사 표식 `source='mcp'`** — `report_versions.source` 는 `String(16)` 자유값이라
      **마이그레이션 불필요**. `_apply_ai_draft` 가 스냅샷을 만들 때 `mcp` 로 표시.
      웹 버전 이력 UI 에 "AI 수정" 배지. ※ 사람이 웹에서 고친 것과 구분되는 게 핵심.
- [x] **`update_report_draft(dry_run=True)`** — 적용하지 않고 **무엇이 바뀔지 요약**만
      반환(블록별 추가/교체/삭제, 검증 경고, 영향 페이지). 게시된 글 수정 시 특히 필요.
- [x] 도구 docstring·SKILL 에 "고치기 전 dry_run, 잘못되면 restore_version" 습관 명시.

**예상 규모**: 백엔드 소, MCP 소. **가장 싸고 가장 급하다.**

> ✅ **구현 완료 (2026-08-21)**. 마이그레이션 없음 — `report_versions.source` 가 자유
> 문자열이라 `'mcp'` 를 그냥 넣었다. 다만 `prune_versions` 가 `source != 'save'` 를
> **영구 보존**하고 있어, 그대로 두면 AI 수정분이 계속 쌓인다 → `ORDINARY_SOURCES =
> ('save','mcp')` 로 넓혀 일상 저장처럼 프루닝되게 했다(`'mcp'` 는 마일스톤이 아니라
> **누가 고쳤나** 표식이므로). `list_versions` 는 백엔드 `id` 를 `version_id` 로 바꿔
> 돌려준다 — 그대로 흘리면 모델이 report id 와 헷갈린다.

## Phase B — 사람과 주고받는 통로 (일하는 방식이 바뀌는 부분)

> 목표: 지시를 채팅으로 옮겨 적지 않는다. **문서 안에서 대화가 끝난다.**

```
사람: 보고서 3장에 댓글 — "결론이 약함, 시험 데이터 근거 추가"
AI:   list_comments → 읽고 → search_reports 로 근거 찾고 → 본문 수정 → reply_comment
사람: 확인 후 스레드 종료
```

- [x] **`list_comments(report_id, status?)`** — `GET /api/comments/reports/{id}/threads`.
      스레드+댓글을 AI 가 읽기 좋은 평평한 형태로(작성자·시각·본문·연결된 블록·상태).
- [x] **`reply_comment(thread_id, text)`** — `POST /api/comments/threads/{tid}/comments`.
- [x] **`resolve_thread(thread_id)`** — `PATCH /api/comments/threads/{tid}` (status).
- [x] **`list_my_notifications(unread_only?, limit)`** — `GET /api/notifications`.
      "나 뭐 할 거 있어?" 에 답하게 한다. 게시취소 요청·리뷰·경보가 여기로 온다.
- [x] **AI 발화 표식** — §6-1 의 (a) 채택: `comments.via` 컬럼(p90) + UI 배지.
      **서버가 요청 헤더 `X-Client: mcp` 를 보고 채운다**(클라이언트 입력 불신).

**예상 규모**: 백엔드 0(전부 존재), MCP 중. **투입 대비 효과가 가장 크다.**

> ✅ **구현 완료 (2026-08-21)**. 마이그레이션 **p90**(`comments.via`). 실제 경로는
> `/api/reports/{id}/threads` · `/api/threads/{tid}/comments` 였다(`/api/comments/...`
> 아님 — comments 라우터가 `/api` 에 마운트된다). 댓글 본문이 tiptap 문서 JSON 이라
> MCP 가 평문↔문서로 변환한다(`_doc_to_text`/`_text_to_doc`) — 리치 JSON 을 그대로
> 주면 모델이 읽기 어렵고 토큰만 먹는다.

## Phase C — 세밀 편집 (체감 최대, 설계 필요)

> 목표: 표에 한 줄 넣으려고 표 전체를 왕복하지 않는다.

현재는 `blocks` 를 주면 그 블록 content 가 **통째로 교체**된다. 그래서 AI 는
`get_report` 로 전체를 읽어 **전부 다시 보낸다** — 토큰 낭비이자, 읽고 쓰는 사이 사람이
고친 내용을 조용히 덮어쓰는 **lost update** 위험이다.

- [x] **`append_rows(report_id, block_id, rows, page?)`** — 표/차트류에 행 추가.
- [x] **`patch_cells(report_id, block_id, patches, page?)`** — `[{row, key, value}]` 로 셀만.
- [x] **`remove_rows(report_id, block_id, row_indexes, page?)`**
- [x] **낙관적 동시성** — `ReportUpdate.expected_revision` 이 **이미 있다**. 세밀 연산에
      `expected_revision` 을 노출해, 그 사이 남이 고쳤으면 409 로 거부하고 AI 가 다시 읽게.
- [x] 대상 위젯 범위 결정: table·chart·pie·progress_bar·milestone 등 **행 개념이 있는 것**만.
      rich_text 같은 건 별도(문단 단위 patch 는 후속).

**예상 규모**: 백엔드 중(정규화·검증 재사용), MCP 소.

> ✅ **구현 완료 (2026-08-21)**. `PATCH /api/reports/{id}/ai-draft/rows`, 마이그레이션 없음.
> **발견**: 행 개념이 있는 위젯은 대부분 `content.rows`(객체 리스트) 규약을 공유한다
> (table·chart·pie·box·waffle·packing·treemap·tree·mind_map·raci·comparison·scatter3d…).
> 그래서 위젯별 분기 없이 **하나의 일반 연산**으로 덮인다. 고친 블록은 원래 작성 경로와
> 같은 정규화(`ai_authoring`)에 다시 태워 숫자 강제·라벨키 매핑을 그대로 받는다.
> `ops` 를 리스트로 받아 여러 연산이 **한 번만 저장**된다(버전·revision 도 1회).
> 없는 block_id 면 **그 페이지에서 가능한 블록 목록**을 알려준다(이름만 틀린 경우가 흔하다).

## Phase D — 자기 점검과 산출물 흐름

> 목표: AI 가 자기 결과물을 확인하고, 최종 산출물(종합보고)까지 잇는다.

### D-1 자기 점검
- [x] **`get_report_outline(report_id)`** — 페이지별 블록 순서·타입·**채움 여부**·검증 경고
      요약. "3쪽 표가 비어 있음", "2쪽 차트에 데이터 없음" 을 AI 가 스스로 잡게 한다.
      **완성본을 못 보는 문제의 저비용 대체재.**
- [ ] (후속) **렌더 확인** — 진짜 완성본은 `[미구현] 헤드리스_내보내기_설계.md` 가 서야
      가능하다. 그게 서면 `export_report(format)` → 파일을 MCP 로 받아 확인.

### D-2 산출물 흐름
- [x] **`list_composites(...)` / `get_composite(id)`** — 종합보고 조회(현재 MCP 도구 0개).
- [x] **`request_composite_item(composite_id, report_id, note)`** — `POST /{id}/requests`.
      **사람이 승인하는 요청 큐**라 안전 모델과 잘 맞는다(AI 가 직접 꽂지 않는다).
- [x] **게시(mount) 경계 정리 — 2단계 확인으로 해결(2026-08-21).** 요청 큐는 만들지
      않았다. 확인해보니 **작성자는 이미 승인 없이 게시**한다(게시 3,474건 중 95%가
      작성자 본인). 큐를 두면 *자기가 자기한테 승인 요청*하는 꼴이라 "AI 로 게시하고
      싶다"는 목적과 어긋난다. 대신 **preview → confirm token → publish** 2단계를
      MCP 경로에만 강제한다(웹은 그대로 한 번에). 토큰은 (사용자·보고서·게시판 집합·
      만료)에 HMAC 서명한 값이라 **저장 테이블이 없고**, 미리 본 것과 다른 대상으로는
      실행되지 않는다. `report_mounts.via='mcp'`(p91)로 경위도 남긴다.

**예상 규모**: D-1 소, D-2 중.

> ✅ **D-1·D-2 구현 완료 (2026-08-21)**. 마이그레이션 없음.
> `GET /api/reports/{id}/outline` 은 본문을 담지 않는다(토큰이 존재 이유). `blocks_order`
> 가 있으면 그게 **화면에 실제로 나오는** 블록이라 그 기준으로 빈 블록을 잡는다
> (AI 초안은 빈 템플릿 블록을 자동으로 숨기므로, 그걸 issue 로 올리면 오탐이 된다).
> **함정**: 종합보고 목록은 `list_in_workspace_tree`(활성 워크스페이스 트리) 스코프라
> MCP 고정 헤더로는 0건이 나온다 — 도구에 `board` 를 받아 **그 호출만** 워크스페이스
> 컨텍스트를 바꾼다(Phase 6 의 `scope=user` 와 같은 문제, 다른 해법).

## 5. 공통 작업 (Phase 무관)

- [x] **요청 크기 상한** — `_enforce_ai_limits`. 폭주(무한 생성·잘못된 루프) 방어선이지
      업무 제약이 아니라서 **실사용 최대치를 크게 웃돌게** 잡았다 — 운영 데이터 기준
      최대 590쪽(문서 가져오기 산출물)·페이지당 34블록·블록당 33행·본문 1.3MB.
      상한: 1000쪽 / 200블록 / 5000행 / 8MB / 한 번에 1000행. 걸리면 조용히 자르지 않고
      **400 으로 무엇이 넘쳤는지** 알려 AI 가 쪼개 재시도하게 한다.
- [x] **SKILL.md 갱신** — 도구 목록 + 절차 4개(댓글 반영·표 한 줄 수정·자기 점검·종합보고 제출).
- [x] **MCP 서버 재시작** — 확인 결과 운영은 **자동**이다(`deploy.sh update` → `cmd_update`
      가 `setup_mcp` 를 다시 돌려 `systemctl restart reportarchive-mcp`). 개발자 로컬만 수동.

## 6. 미결정 — 착수 전 결정 필요

1. **AI 가 단 댓글을 어떻게 표시할 것인가.** MCP 는 사용자 토큰으로 동작하므로 AI 의 답글이
   **그 사람이 쓴 것처럼** 보인다. 선택지:
   (a) 댓글 모델에 `via` 컬럼 추가 + UI 배지 (정공법, 마이그레이션 1개)
   (b) 본문에 접두사 규약(`[AI]`) — 싸지만 위조·검색 오염 가능
   (c) 그냥 둔다 — 비추천. 협업 신뢰가 깨진다
2. **게시(mount)를 AI 에게 열 것인가 — 보류(2026-08-21).** `request_publish` 를 하려고
   보니 **게시 요청 큐가 없다**(게시취소 요청만 존재. 게시는 작성자·매니저가 바로 한다).
   큐 신설은 별도 기능이라 이 로드맵 범위 밖으로 뺀다. 현행 유지 = **AI 는 게시하지 않는다.**
   대신 종합보고는 요청 큐가 이미 있어 `request_composite_item` 으로 같은 패턴을 만족한다.
3. ~~**세밀 편집의 충돌 정책.**~~ → **(a) 409 후 AI 재시도 채택** (2026-08-21 구현).
   자동 병합은 조용한 덮어쓰기를 부른다.

## 10. MCP 서버 전수 점검에서 나온 버그 (2026-08-21, 후속2)

44개 도구를 **진짜 프로토콜로 전부 호출**해 훑었다(정상 경로 + 없는 자원 + 경계값
+ 잘못된 형식 + LLM 이 죽은 상태). 대부분은 잘 막고 있었고 — 행 범위 밖, 없는 블록,
토큰 위조·대상 불일치, SSRF, 파일 크기 상한, 멱등 upsert 는 전부 제대로 거절한다 —
아래 5건이 나왔다.

### ① `prepare_upload` 가 만드는 curl 이 깨졌다 (심각)
공백·괄호가 있는 파일명에서 **셸 구문 오류**가 났다. "내 파일 (사본).png" 같은
이름은 흔한데, 이건 문서상 **로컬 파일 업로드의 기본 경로**다.

    --data-binary @/tmp/내 파일 (사본).png    # bash: syntax error near `('
    ...?filename=내 파일 (사본).png            # URL 에 raw 공백

경로는 `shlex.quote`(셸), 파일명은 `urllib.parse.quote`(URL)로 각자 이스케이프한다.
같은 이름으로 실제 업로드까지 돌려 확인했다.

### ② 행 추가가 **거짓 보고**를 했다 (심각)
행은 `{"열키": 값}` 객체여야 하는데 문자열·숫자를 보내면 정규화가 조용히 버린다.
그런데 응답은 `count: 요청한 수` 를 그대로 줘서, AI 가 사용자에게 "1행 추가했습니다"
라고 **거짓말**을 했다(경고도 없었다). 실제 증가분으로 보고하고, 모자라면 왜 그런지
경고를 남긴다. 확인 수단인 `row_counts` 도 실제 적용 응답에 실었다 — dry_run 엔
있는데 여기만 없어서 결과를 확인하려면 다시 읽는 수밖에 없었다.

### ③ 오류마다 같은 문장을 두 번 실어 날랐다
`_unwrap` 이 `{"error": msg, "detail": {success, message}}` 로 message 를 중복시켰다.
envelope 밖의 정보(`errors` 코드 등)가 있을 때만 `detail` 을 싣는다.

### ④ 잔가지 둘
- `list_templates` 애너테이션이 `-> list` 인데 실제로는 dict 를 준다(스키마가 거짓).
- `get_report(page=0)` 이 "9쪽뿐입니다" 라고 원인을 잘못 짚었다 → "1 이상이어야".
- `get_guide` 의 `more_topics` 가 하드코딩 튜플에서 나와, GUIDE.md 에 주제를 더해도
  서버가 안 알려줬다(가이드를 서버가 쥐기로 한 취지와 어긋난다) → 파일에서 뽑는다.

### ⑤ 버그는 아니지만 고친 것 — 테스트 스위트가 매달리던 원인
dev `.env` 가 `LLM_BACKEND=openai` + Windows 호스트 llama-server(:8080)를 가리키는데,
그게 안 떠 있으면 LLM 을 타는 테스트가 **connect 에서 매달려** 스위트가 통째로 멈춘다
(15분 넘게 걸렸다. 그 전엔 "10 failed, 7 errors" 같은 산발적 실패로 나타났다).
`tests/conftest.py` 에서 app import 전에 `LLM_BACKEND=mock` 을 기본값으로 박았다 —
"실행할 때 환경변수 붙이는 걸 기억하기"는 재발할 수밖에 없다.

**정상 확인된 것**(회귀 시 참고): 행 범위/없는 블록/빈 인자 거절, dry_run 무저장,
expected_revision 가드, 게시 2단계 토큰(위조·대상 불일치 모두 거절), 파일 바이트
왕복 일치, 댓글 `via='mcp'` 왕복, 온톨로지 쓰기 멱등·축/관계 검증, SSRF(사설망·
file://) 차단, 업로드 티켓 인증, LLM 이 죽어도 `search_reports` 는 0.5초에 폴백.

## 11. 되돌리기 안전망의 전제 메우기 (2026-08-21, 후속3)

§9-④ 에서 되돌리기에 미리보기·동시성 가드를 붙였는데, **되돌릴 지점 자체가 없는
보고서**가 있었다. `record_version` 은 저장 **뒤** 본문을 찍으므로, 버전 기능이
생기기 전(2026-05~06)에 만들어진 보고서는 이력이 0개다. 그 상태에서 AI 가 처음
수정하면 남는 버전은 **수정된 결과 하나뿐**이고, 되돌리면 AI 편집본으로 돌아간다 —
**원본은 복구 불가**였다. 대상 104건, 그중 이미 게시돼 AI 가 고칠 수 있는 것이 85건.

**일회성 백필로 끝냈다(p93)** — 최근 30일 생성분 854건이 전부 버전을 가지므로
지금 생성 경로는 항상 v1 을 시딩한다. 즉 **닫힌 집합**이고 더 생기지 않는다.
런타임 편집 경로는 건드리지 않았다(부작용 위험 0).

- `source='baseline'` — `ORDINARY_SOURCES`('save','mcp')에 없어 `prune_versions`
  가 건너뛴다 = **영구 보존**. 수정이 30개를 넘겨도 최초 상태로 돌아갈 길이 남는다.
- 마이그레이션은 관례대로 모델을 import 하지 않고 직렬화를 복제했다. 그 복제가
  어긋나면 **되돌리려는 순간에야** 터지므로, 테스트에서 코드 경로와 **같은 해시**가
  나오는지 검사한다(`test_baseline_version_seed.py`).
- 이력 화면 `SOURCE_LABEL` 에 `mcp`('AI 수정')·`baseline`('최초')이 빠져 있어
  원문이 그대로 노출됐다 — 함께 보강.

**검증**: 시딩된 보고서를 AI 로 고친 뒤 baseline 으로 되돌려 **원본 제목이 복구되는
것까지** 확인했다(버전 흐름 `baseline → mcp → restore`).

## 12. AI 가 자기 쓰레기를 치우게 (2026-08-21, 후속4)

**만들기는 쉬운데 치우는 건 불가능한 비대칭**이 있었다. 실제로 §10 점검 중 만든
임시 보고서를 DB 로 직접 지워야 했다 — MCP 로는 방법이 없었다. 백엔드엔
`POST /{id}/trash`(소프트삭제, 복구 가능)가 이미 있는데 도구로 안 열려 있었다.

### 삭제 범위 — 셋을 모두 요구한다
`can_trash_report`(소유자 **또는 시스템관리자**)만으론 부족하다. 관리자 토큰으로
MCP 를 쓰면 남의 글까지 닿고, 게시된 글은 조직이 보고 있어 사라지는 것 자체가
사건이다. 그래서 MCP 경로에만 `_ai_trash_guard` 를 건다:

    본인 소유  ·  미게시  ·  drafting(작성중)

가드는 **백엔드**에 있다(MCP 계층은 보안 경계가 아니다 — 게시 확인토큰과 같은
방식으로 `X-Client: mcp` 를 보고 좁힌다). 웹 경로는 그대로다. 거절할 때는
**사람이 어떻게 하면 되는지**까지 담는다("먼저 웹에서 게시취소한 뒤…") — 모델이
사용자에게 그대로 전할 문장이기 때문이다. 복구 도구는 만들지 않았다(웹 휴지통).

### 치우는 것보다 안 만드는 게 낫다 — create 에 dry_run
`update_report_draft` 엔 있는데 create 에만 없었다. 형식이 틀리면 블록이 **조용히
버려지는데**(§10-② 와 같은 결) 만들고 나서야 안다. 이제 저장 없이 페이지별로 들어갈
block_id 와 `warnings` 를 먼저 준다. 미리보기와 실제가 갈라지지 않게 검증
(`_validate_pages`)은 실제 생성과 **같은 것**을 태운다.

### 겸사겸사 — data:null 응답이 빈 문자열로 나갔다
`trash_report` 첫 검증에서 결과가 `""` 였다. 백엔드가 `data: null` 을 주는
성공 응답(삭제·복구처럼 돌려줄 게 없는 것)을 `_unwrap` 이 그대로 흘려서,
**모델이 성공했는지 알 수 없었다**(조용한 무동작과 구분 불가). `{"ok": true,
"message": ...}` 로 최소 확인 신호를 만든다. 삭제·복구 계열 전부에 해당한다.

## 13. 게시취소 — 요청까지만 (2026-08-21, 후속5)

게시는 2단계 확인까지 붙여 열어놨는데 **반대 방향은 아예 없었다.** 가이드가
"잘못 올렸으면 웹에서 게시취소하라"고 사람에게 넘겼다 — 조직 전체에 문서를
노출시키는 건 되는데 되돌리는 건 못 돕는 구조였다.

**요청까지만 연다.** `POST /{id}/takedown-requests` 는 원래 *요청자가 관리하는
게시판이면 즉시 게시취소*한다. MCP 는 사용자의 토큰으로 동작하므로, 매니저가
AI 를 쓰면 그 자리에서 내려간다 — 사람이 보고 있던 문서가 사라지는 일이라
그건 사람이 한 번 봐야 한다. 그래서 `request_only` 를 추가하고 라우트가
`X-Client: mcp` 일 때 강제한다(게시 확인토큰·안건 제출과 같은 규약).

    게시: preview → 확인토큰 → 즉시
    취소: 요청 → 사람 승인          ← 비대칭이지만 의도된 방향

`withheld_auto` 로 "당신이 매니저인 게시판" 을 돌려준다. 이걸 안 주면 요청이
큐에 박힌 채 잊힌다 — 모델이 "웹에서 직접 승인하시면 됩니다" 라고 말할 수 있어야
한다. 웹 경로는 그대로다(매니저가 화면에서 누르면 여전히 즉시).

**부수 수정**: 새 도구가 `board` 를 쿼리에 그대로 끼워 넣고 있었다 — §10-① 에서
셸을 깨뜨린 것과 같은 습관이라 바로 인코딩했다. 이 엔드포인트는 이름 해석이
없고 slug 정확일치라, 도구 설명에도 그렇게 적었다.

## 14. 도구 설명 무게 줄이기 (2026-08-21, 후속6)

`get_guide` 도입으로 **안내서의 최신성** 문제는 풀었지만(v0.148.0), **도구 목록

### 가르는 기준 — 이게 핵심이다

가이드는 **안 불러올 수 있다.** 그러니 안 불러온 상태에서도 사고가 안 나야 한다.

알리라는 지시, `mine=True`(모델은 사용자 이름을 모른다 — `author` 로 풀면 **에러
없이 엉뚱한 답**), `board` vs `author_org` 축 혼동, 업로드 256KB 상한, dry_run 습관.
옮긴 것: 필터 값 형식·반환 형태·위젯 content 예제·인자별 병합 의미·업로드 경로 판단.

### 검증에서 잡은 것
도구에서 뺐는데 **가이드에도 없는** 내용이 3건 있었다(메타데이터 `report_type_id`·

가리키는 항목이 실제로 각 주제에 있는지 기계적으로 검사해 잡았고, 프로토콜로

## 15. 잔가지 셋 (2026-08-22, 후속7)

### 반환 형태 통일 — `create_report_draft`
다른 도구는 전부 `report_id` 인데 여기만 `report.id`(중첩)에 **전체 report 객체**를
실었다(owner_email·잠금 필드까지). 모델이 헷갈리는 자리이고 토큰도 샌다.
`{report_id, title, page_count, phase, warnings, url}` 로 바꿨다 — **2,230자 → 133자**
(생성할 때마다). `/from-answer` 가 이 경로를 재사용하므로 같이 바뀐다.

### 보고서 첨부 나열 — `GET /reports/{id}/files`
`files` 테이블엔 report 연결이 없다. 파일은 본문 content 안에 `file_id` 참조로만
존재한다. 그래서 본문을 훑는데, **위젯 타입을 열거하지 않고 키 이름으로 재귀 수집**
한다 — file_id 를 담는 위젯이 이미 7종이고 모양이 제각각이라(비교표는 셀 안), 타입을
나열하면 새 위젯이 생길 때 **조용히 빠진다**. 첨부를 나열하는 도구가 일부만 보여주는
건 없느니만 못하다. 본문은 참조하는데 파일이 지워진 경우 `missing: true` 로 알린다.

### 저장검색 실행 — `GET /saved-searches/{sid}/results`
프론트는 저장 필터를 자기가 검색 화면에 되살린다. **AI 는 그렇게 못 한다** — 저장
필터는 내부 id·camelCase 라 도구 어휘와 다르고, 모델이 손으로 옮기면 에러 없이 다른
결과가 나온다. 서버가 돌려주되, **구독 알림과 같은 필터 경로**를 탄다
(`matching_report_ids` 로 분리해 공유) — 갈라지면 "알림은 왔는데 열어보니 없다" 가 된다.
반환 모양은 `/reports/browse` 와 같다(`browse_projection` 추출).

### 경보 — 시스템 관리자 전용
`alerts` 라우트는 전부 `require_system_admin` 이라, 도구 설명에도 그렇게 적었다
(온톨로지 쓰기와 같은 취급). 일반 사용자는 자기에게 온 것만 `list_my_notifications`.

### 또 나온 빈 응답
`list_saved_searches` 가 0건일 때 도구 결과가 **빈 문자열**이었다(백엔드가 리스트를
그대로 준다). 모델이 "못 불렀다" 와 "없다" 를 구분 못 한다 — §12 의 `data:null` 과
같은 결이라 다른 목록 도구처럼 `{saved_searches, count}` 로 감쌌다.

**도구 51개 · 설명 18,417자** — 5개를 늘렸는데도 감량 전(20,105자)보다 가볍다.

## 16. 백지에서 시작하지 않기 — 프리셋·복제 (2026-08-22, 후속8)

MCP 로 글 쓸 때 가장 큰 격차는 **사람이 실제로 쓰는 방식을 AI 가 못 쓴다**는 것이었다.
사람은 빈 템플릿에서 시작하지 않는다 — 저장해둔 양식으로 시작하거나 지난 보고서를
복제해서 숫자를 갈아끼운다. 백엔드엔 프리셋 6개 라우트와 `POST /{id}/copy` 가 이미
다 있었고 **MCP 에만 없었다.** 그래서 AI 는 매번 구조를 새로 짜야 했고, 회차마다
형식이 흔들리고 토큰도 크게 들었다.

도구 4개: `list_presets` · `create_report_from_preset` · `copy_report` ·
`save_report_as_preset`.

### 왜 템플릿 생성이 아니라 프리셋인가
"이 형식으로 시작" 요청의 대부분은 **템플릿(구조 정의)이 아니라 프리셋(채워진 내용)**
이다. 그리고 템플릿은 열면 안 되는 이유가 분명하다:
- 템플릿은 **전 직원 작성 picker 에 뜨는 공용 네임스페이스**이고 이미 120개다.
- 보고서가 한 번이라도 참조하면 **삭제가 409 로 막힌다** — 사실상 영구다.
- 실제로 이 세션의 테스트가 템플릿 18건을 published 로 흘렸고, 전부 보고서가 물려
  있어 지우려면 보고서부터 지워야 했다. **자동화가 공용 목록에 쓰면 이렇게 된다.**

### 프리셋에도 같은 위험이 있었다 — 기본값을 바꿨다
`PresetCreate.owner_workspace_slugs` 는 **생략하면 전사 공개**다(화면에선 사람이
명시적으로 고르므로 문제 없다). AI 가 생략하면 그대로 전사에 얹힌다.
그래서 라우트가 `X-Client: mcp` 이고 범위가 생략되면 **개인 양식으로 떨어뜨린다**
(`personal-{uid}` 단독 소유는 `assert_can_scope_to` 가 누구에게나 허용). 부서·전사에
올리려면 AI 도 slug 를 명시해야 하고, 그때는 계정 권한으로 다시 판정된다.
웹 경로는 그대로다(테스트로 양쪽 다 고정).

### 도구 설명에 넣은 안전선
양식·복제로 시작한 보고서는 **내용이 지난 회차 것**이다. 그대로 두면 지난주 수치가
그대로 나간다 — "만든 뒤 반드시 갱신하고, 무엇을 갱신했고 무엇을 그대로 뒀는지
사용자에게 알려라" 를 설명과 가이드 양쪽에 넣었다(가이드는 안 불러올 수 있으므로).
남의 보고서를 복제하면 출처를 밝히라는 것도 같은 이유로 도구 쪽에 뒀다.

상호참조(#) 무결성. 상호참조는 애초에 **AI 가 만들 방법이 없어서**(rich_text 작성

## 18. 상호참조 — 만들 수 있었는데 아무도 몰랐다 (2026-08-22, 후속10)

본문에서 "그림 3"·"표 2" 로 가리키는 상호참조는 이 시스템의 기능이다(REF_CATEGORIES
12종, 번호는 **렌더 시 계산**되고 저장하지 않아 순서가 바뀌면 자동 재번호). 그런데
`rich_text` 작성 규칙 9,613자에 "참조" 가 **한 번도 안 나왔다.** 그래서 AI 가 쓴
보고서는 "아래 표에서 보듯이" 처럼 말로만 가리켰고, 순서가 바뀌면 틀린 문장이 됐다.

### 확인해보니 — 막힌 게 아니라 안 적혀 있었을 뿐
- 저장 형태는 rich_text 행 html 안의 앵커:
  `<a data-mention-type="block" data-mention-id="tbl" data-mention-page="0">표 1</a>`
- 백엔드엔 HTML sanitize 가 없고(렌더 시점에 한다), 프론트 `SANITIZE_OPTIONS` 가
  `data-mention-type|id|page` 를 **명시적으로 허용**한다.
- AI 경로(`items[].html`)로 넣어봤더니 **정규화가 그대로 보존**했다(실측).

즉 **문서만 없었다.** 작성 규칙(`authoring_rules.json`)에 형식·주의사항을 넣었다.

### 함정: `data-mention-page` 는 0-base
프론트가 배열 인덱스로 만들기 때문이다. 그런데 **MCP 도구 인자의 `page` 는 전부
1-base** 다(get_report·update_report_draft·행 조작). 한 칸씩 어긋나기 딱 좋고,
틀리면 화면에 "(삭제된 항목)" 으로 뜨는데 **AI 는 그걸 못 본다.**

그래서 outline 에 깨진 참조 검사를 넣되, **한 칸 옆에 있으면 그렇다고 짚어준다**:

    1쪽 'body' 의 상호참조가 2쪽 'tbl' 를 가리키는데 그런 블록이 없습니다
    (화면엔 '(삭제된 항목)' 으로 뜹니다). — 1쪽에 있습니다.
    data-mention-page 는 **0부터** 셉니다(1쪽이면 "0").

규칙 → 작성 → 점검 고리가 닫혔다. 프로토콜로 전 구간 확인했다.

## 19. 여러 보고서를 재료로 — 본문 추림 (2026-08-22, 후속11)

"지난 4주 주간보고 모아 월간보고 써줘" 를 하려면 보고서를 하나씩 읽어야 했다.

`report_ai_summaries` 를 재료로 쓰려 했는데, 실측해보니 **5,128건 중 13건(0.2%)**

게다가 그중 하나는 mock LLM 출력(프롬프트 원문)이 그대로 들어 있었다. 재료로 삼을

권한도 필요 없다 — 요약은 이걸 받아 모델이 직접 한다.

### 조용히 빠지지 않게
볼 수 없거나 없는 보고서는 `skipped` 에 **사유와 함께** 담는다. 빠진 걸 모르면
"다 봤다" 로 오해되고, 그건 이 세션에서 반복해 잡은 실패 유형이다(빈 응답·거짓
count). 도구 설명에도 "몇 건을 재료로 썼는지 사용자에게 알려라" 를 넣었다.

### 라우트 순서 함정
`/digest` 는 정적 path 라 동적 `/{report_id}` **위에** 등록해야 한다. 처음엔 아래에
뒀다가 422 가 났다(FastAPI 가 "digest" 를 report_id 로 해석). 파일에 이미 같은
주석이 있었는데 밟았다.
