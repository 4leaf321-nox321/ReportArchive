# 개발가이드

개발자가 로컬에서 작업할 때의 절차. 운영 배포 절차는 `배포방법.md` 참고.

## 모델/스키마 변경 시

```bash
# 1. 모델 파일 편집 (예: backend/app/modules/<module>/models.py)
# 2. 마이그레이션 파일 자동 생성
cd backend
alembic revision --autogenerate -m "변경 요약"

# 3. 생성된 파일 검토
#    migrations/versions/<hash>_변경요약.py
#    autogenerate가 항상 정확하지는 않음. 특히:
#    - 컬럼 rename → drop + add 로 잘못 감지될 수 있음 (데이터 손실 위험)
#    - 인덱스 / 제약조건 변경은 누락될 수 있음
#    필요하면 upgrade() / downgrade() 함수를 직접 수정

# 4. 모델 + 마이그레이션 파일을 함께 커밋
git add app/modules/.../models.py migrations/versions/*.py
git commit -m "schema: 변경 요약"
git push
```

이후 운영 서버에서는 `git pull && python scripts/setup_and_upgrade_db.py`만 실행하면 자동 적용됨.

## 로컬에서 마이그레이션 적용 / 롤백

```bash
alembic upgrade head     # 모든 미적용 마이그레이션 적용
alembic downgrade -1     # 한 단계 롤백
alembic current          # 현재 리비전 확인
alembic history          # 변경 이력
```

또는 `python scripts/setup_and_upgrade_db.py` (운영과 동일한 명령) — 결과는 같음.

## 새 백엔드 모듈 추가

1. `backend/app/modules/reports/`를 복제해서 `<your_module>/` 생성
2. `routes.py`, `schemas.py`, `services.py`, `models.py` 수정
3. `backend/app/modules/__init__.py`에 라우터 등록
4. `backend/scripts/setup_and_upgrade_db.py` 상단의 모델 import 라인 추가
5. (모델이 있으면) 위의 "모델/스키마 변경" 절차로 마이그레이션 생성

## 새 프론트엔드 모듈 추가

1. `frontend/src/modules/reports/`를 복제해서 `<your-module>/` 생성
2. `<YourModule>Page.jsx`, `api.js` 수정
3. `frontend/src/App.jsx`에 라우트 추가

## 새 위젯 추가

보고서 위젯(`heading`, `rich_text`, `table` 등)을 추가할 때 손대야 하는 자리.
순서대로 진행하면 누락 없음.

1. **백엔드 등록** — `backend/app/widgets/registry.py`

     `content_schema_for`, `default_props`) 정의
   - 하단 `WIDGET_REGISTRY` 튜플에 추가
2. **프론트 위젯 컴포넌트** — `frontend/src/modules/templates/widgets/<Name>.jsx`

   - `Preview` — 템플릿 캔버스의 자리표시 미리보기

3. **위젯 레지스트리** — `frontend/src/modules/templates/widgets/index.js`
   - lucide 아이콘 import + 컴포넌트 3종 import
   - `WIDGET_RENDERERS` 객체에 `<type>: { Icon, PropsPanel, Preview, Editor }`
4. **셀 기본 크기** — `frontend/src/modules/templates/widgetBuilder.js`
   - `DEFAULT_BLOCK_SIZE`에 `<type>: { col_span, row_span }` 추가.
   - 없으면 기본 12×2로 떨어짐 (동작은 하지만 어색)

### AI가 생성할 위젯이라면

5. **AI 프롬프트 V1 예시** — `ReportDetailPage.jsx` `buildAiPrompt`
   - `examples` 배열의 `### <type> (라벨)` 블록 추가 (props/content 예시 + 주의사항)
6. **AI 프롬프트 V2 예시** — `ReportDetailPage.jsx` `buildAiPromptV2`
   - 동일 블록을 V2 examples에도 추가
7. **커버리지 체크 집합** — `ReportDetailPage.jsx` `PROMPT_COVERED_WIDGETS`
   - type 문자열 추가 (AI 프롬프트 다이얼로그 사이드바의 "미등록" 표시 방지)

### Word 내보내기 대응

8. **`exportReportToDocx.js`** `convertBlock` switch
   - 텍스트 기반 위젯이면 전용 converter (paragraph/table) 함수 작성
   - 시각 위젯(차트/플로우/마일스톤처럼)이면 기존 `convertVisualBlock` case에
     case 라벨만 추가 (html2canvas로 PNG 캡처)
   - 누락 시 default 가지로 빠져 "[지원하지 않는 위젯]" 텍스트만 찍힘

### 백엔드 테스트

9. **`backend/tests/test_widgets_api.py`**
   - `test_widgets_endpoint_returns_full_catalog`의 expected 타입 리스트에 추가

### 선택 (옵션 기능)

- **`WIDGET_DEFAULT_SECTION_CODE`** (`ReportDetailPage.jsx`) — 신규 블록 추가
  시 단락 구분을 자동 태깅하고 싶을 때 (현재 `milestone`만 등록)
- **`WIDGETS_WITH_REPORT_STYLE`** (`ReportDetailPage.jsx`) — 보고서별
  text_style 오버라이드 패널을 띄울 때 (현재 비어있음 — RichText는 자체 패널
  존재)
- **`seedContentFromTemplate`** (`ReportDetailPage.jsx`) — 새 블록의 초기
  content를 template props로부터 채울 때 (현재 heading의 `default_text`만 예)

### 손댈 필요 없음 (자동 처리)

- **로컬 JSON 저장/불러오기** — `draft.pages` 자체를 직렬화하므로 타입 무관
- **PDF 인쇄, HTML 저장** — DOM 캡처라 view 모드에서 보이는 그대로 처리됨
- **백엔드 validation** — `props_schema`/`content_schema_for`만 정의하면
  jsonschema가 자동 검증
- **단락 구분 헤더 / autoFit 측정** — block.id 기준이라 타입 무관

## 시각 위젯에 어노테이션 얹기

이미 차트와 단일 이미지에는 어노테이션이 붙어있음 (`frontend/src/shared/annotations/`). 새 시각 위젯에 같은 기능을 얹고 싶을 때 따라가는 경로:

### 1. 어댑터 작성

좌표 공간을 정해서 toPx / fromPx / snap / bounds 를 구현. 두 가지 참고:

- `ChartAnnotationAdapter.js` — Recharts 의 스케일에서 픽셀 추출. 좌표공간 `data`.
- `ImageAnnotationAdapter.js` — DOM 요소의 bounding box 측정. 좌표공간 `image_pct` (0~1).

새 위젯이 시간축이라면 `data_relative` (도메인 끝에서 -7d 같은 anchor) 패턴도 고려 가능 — 다만 backend `ANNOTATION_SCHEMA.coord_space` enum에 새 값을 추가해야 함.

### 2. 백엔드 schema에 슬롯 추가

```python
# backend/app/widgets/registry.py
"annotations": _ANNOTATIONS_FIELD,
```

`additionalProperties: False` 인 content schema 라면 이 한 줄을 properties 에 추가하면 끝. ANNOTATION_SCHEMA 는 차트/이미지/마일스톤이 공유.

### 3. 위젯 컴포넌트에 어노테이션 surface 마운트

`Chart.jsx` / `Image.jsx` 의 `AnnotatableImageBox` 가 참고할 만한 패턴. 묶음:

- `useAnnotationStore({ annotations, onChange })` — 상태 + undo/redo + selection
- `useAnnotationInteractions({ store, adapter, readOnly })` — body 드래그 / handle 리사이즈 / 라벨 더블클릭
- `<AnnotationToolbar />` — 도구 토글 (edit only)
- `<AnnotationCountBadge />` — 50/200 soft-limit 안내 (edit only)
- 외부 `<svg>` 안에 `<SelectionMarquee>` + `<AnnotationContents>` — 항상 렌더 (read-only 에서도 annotation 자체는 그려짐)
- `<InteractiveOverlay>` — 도구 활성 시만 마운트, 생성 클릭 잡음
- `<AnnotationLabelEditor>` / `<AnnotationStyleBar>` — edit only

`Esc` / `Delete` / `Cmd+Z` / `Cmd+Shift+Z` 키바인딩은 호스트가 등록. Chart 와 Image 에 동일 패턴이 있음 — 새 위젯 만들 때 함수로 추출해도 좋음.

### 4. Export 대응

- **HTML / PDF**: SVG 라 자동. 별도 처리 불필요.
- **DOCX**: `exportReportToDocx.js` 의 `convertBlock` 에서 위젯 case 처리.
  - 어노테이션이 있는 cell 은 html2canvas 로 캡처 (위젯 + SVG overlay 가 함께 PNG 로 구워짐).
  - 라벨 텍스트는 `convertAnnotationLabels` 로 captioning — DOCX 검색 가능하게.

### 알려진 한계

- 이미지 갤러리 (max_count > 1) 는 어노테이션 미지원 — 어느 파일에 속한 마크인지 모델에 없어서.
- coord_space 가 `data_relative` 인 경우 fromPx/toPx 가 안 만들어져 있음 — D8 보류 항목.
- 호버 dim 효과는 fill 있는 도형 (vrange/hrange/rect) 만 적용 — 라인/점/화살표는 데이터 안 가리므로 의도된 동작.
- 모바일 / 터치 환경에서 핸들 잡기가 어색할 수 있음 (작은 핸들). 필요 시 G2 (view-only 모드 강제) 검토 — 현재는 미구현.

## 로컬 개발 서버 실행

```bash
# 백엔드
cd backend && source venv/bin/activate && python run.py     # http://localhost:3000

# 프론트엔드
cd frontend && npm run dev                                  # http://localhost:3001
```

`backend/.env`의 `APP_ENV=development` (기본값) 상태에서 hot reload 활성화.
