# 배포 구조 — 무엇이 어디에서 도는가

운영 서버에 배포된 ReportArchive가 런타임에 어떻게 구성되는지, 어떤 의존성이
컨테이너 안에 박혀 있고 어떤 게 호스트 OS에 깔려 있어야 하는지 정리한 문서.

배포 *절차* 자체는 `deploy/README_OPERATOR.md` 와 `배포방법최종.md` 참조.
이 문서는 "왜 이렇게 갈라져 있는가"에 초점.

---

```
└────────────────────────────────────────────────────────────────┘
```

## SIF (컨테이너) 안에 박혀 있는 것

apptainer 빌드 시점에 못박혀, 운영 서버에서 별도로 깔 필요가 없는 것들.

### OS / 런타임 베이스
- **Ubuntu 24.04 LTS** — `deploy/apptainer.def` 의 `From: ubuntu:24.04`
- **Python 3.12** — `apt-get install python3.12 python3.12-venv python3-pip`

### 백엔드 Python 의존성 (`backend/requirements.txt`, 모두 `==` 고정)

| 영역 | 패키지 |
|---|---|
| FastAPI 코어 | fastapi 0.115.5, uvicorn[standard] 0.32.1, python-multipart 0.0.17 |
| Data validation | pydantic 2.10.3, pydantic-settings 2.7.0, email-validator 2.2.0 |
| DB | SQLAlchemy 2.0.36, psycopg[binary] 3.2.3, alembic 1.14.0 |
| 인증 | passlib 1.7.4, bcrypt 4.0.1, python-jose[cryptography] 3.3.0, PyJWT 2.10.1 |
| 환경/유틸 | python-dotenv 1.0.1, httpx 0.28.1, requests 2.32.3, jsonschema 4.23.0 |
| Office 출력 | python-pptx 1.0.2, python-docx 1.2.0, openpyxl 3.1.5 |
| 테스트 | pytest 8.3.4, pytest-asyncio 0.25.0 |

> `bcrypt`는 4.0.1로 의도적 고정 — passlib 1.7.4가 4.1+ 와 비호환.

### 프론트엔드 (빌드 산출물만)

`frontend/dist/` 의 번들된 HTML/JS/CSS만 SIF에 들어감. 즉:

- **운영 서버에 Node.js / npm 불필요**.
- TipTap, React, Radix UI, recharts, vite, eslint, dompurify 등은 모두 **빌드 타임** 의존성. 최종 산출물(dist)에는 번들/트리쉐이크된 결과물만 존재.
- 프론트엔드 소스 의존성은 `frontend/package.json` 참조 (caret 범위로 선언, 실제 락 버전은 `package-lock.json`).

### 컨테이너 내 서비스 기동
- `apptainer.def` 의 `%runscript` / `%startscript` 가 `python run.py` 호출 → uvicorn:3000 가동.
- `APP_ENV=production` 환경에서 `UVICORN_WORKERS=4` 로 멀티 워커.

## 호스트 OS에 있어야 하는 것 ("외부 의존")

`deploy.sh prepare` 또는 운영팀이 미리 깔아둬야 하는 것들. SIF 안에 넣을 수 없거나, 데이터 분리가 필요한 컴포넌트.

| 항목 | 역할 | 비고 |
|---|---|---|
| **apptainer** (1.x) | SIF 런타임 | 개발 환경 1.5.0, Ubuntu 24.04 universe 1.3.x. 1.x 시리즈 내 SIF 하위호환. |
| **PostgreSQL** (16.x 기준) | 영속 DB | 컨테이너 안에 두면 SIF 교체 시 데이터가 사라지므로 의도적으로 host-side. SIF는 `localhost:5433` 로 접속 (운영 머신의 다른 Postgres 인스턴스와 충돌 회피용 비표준 포트). |
| **systemd** | 서비스 라이프사이클 | `reportarchive.service` 유닛이 `apptainer run app.sif` 실행. |
| **python3** (호스트) | `deploy.sh` 내부 유틸 | 시크릿 키 생성(`python3 -c 'import secrets; ...'`) 용도 한정. 앱과는 무관. |
| **ca-certificates** | TLS 루트 트러스트 | DB·외부 호출용. |
| **nginx** (선택) | 리버스 프록시 / 정적자산 캐시 / TLS 종단 | `nginx/nginx.conf.example` 참조. 단일 머신 운영이면 생략 가능 — FastAPI 가 `SERVE_FRONTEND_DIST` 모드로 자체 서빙. |

### 호스트–컨테이너 사이의 bind-mount

`reportarchive.service.template` 에서 다음 셋을 컨테이너 안으로 노출:

| 호스트 경로 | 컨테이너 경로 | 모드 | 이유 |
|---|---|---|---|
| `<INSTALL_DIR>/.env` | `/opt/app/backend/.env` | ro | DB 비밀번호·시크릿. SIF에 박지 않음 |
| `<INSTALL_DIR>/uploads/` | `/data/uploads` | rw | 업로드 파일 영속 |
| `<INSTALL_DIR>/logs/` | `/data/logs` | rw | 로그 영속 |

## 빌드 타임에만 필요한 것 (운영 서버에 절대 들어가지 않음)

| 항목 | 어디서 쓰임 |
|---|---|
| **Node.js / npm** | `frontend` 디렉터리에서 `npm install && npm run build` → `dist/` 생성 |
| **개발자 머신의 apptainer** | `apptainer build deploy/app.sif deploy/apptainer.def` 로 SIF 빌드 |
| **Docker** (registry 접근) | `Bootstrap: docker, From: ubuntu:24.04` — 베이스 이미지를 가져올 때만 |
| **vite, eslint, tailwind 등** | 프론트엔드 빌드 도구. 산출물(dist)에는 트리쉐이크된 결과만 남음 |

---

## 한 줄 요약

운영 서버에 **apptainer · PostgreSQL · systemd** (그리고 선택적으로 **nginx**) 만 있으면 되고, 나머지 모든 앱 의존성(Python 인터프리터·백엔드 라이브러리·프론트엔드 자산)은 단일 `app.sif` 파일 안에 격리되어 있다. 이것이 폐쇄망/단일 번들 배포의 핵심 이점.

## 부록 — 자주 헷갈리는 부분

**Q. 프론트엔드 의존성(React, TipTap 등)은 운영 서버에서 어떻게 도는가?**
A. 안 돕니다. Vite가 빌드 시점에 모두 한 덩어리 JS/CSS로 묶어버립니다. 운영 서버가 보는 건 정적 파일뿐이고, 브라우저가 그걸 받아 실행합니다.

**Q. apptainer 버전이 SIF 빌드 환경(1.5)보다 낮으면(예: 1.1) 안 돌까?**
A. 거의 다 돕니다. SIF 포맷은 1.x 시리즈 내 하위호환입니다. 다만 CVE 패치 누락이 있으니, 가능하면 운영 서버 apptainer를 최신 라인으로 올리는 게 좋습니다. 자세한 처리는 `deploy/README_OPERATOR.md` 의 폐쇄망 절차 참조.

**Q. DB도 컨테이너에 넣지 그랬나?**
A. PostgreSQL은 stateful(데이터·WAL·설정). 컨테이너 안에 두면 SIF를 새 버전으로 교체할 때 데이터가 같이 날아가거나, 별도의 bind-mount 설계가 필요해 복잡도가 급증합니다. 호스트 서비스로 두고 `localhost:5433` 로 붙는 게 운영상 단순합니다.

**Q. nginx 가 꼭 필요한가?**
A. 단일 머신 운영이면 안 깔아도 됨. `.env` 에 `SERVE_FRONTEND_DIST=/opt/app/frontend/dist` 를 켜면 FastAPI 가 정적 자산까지 서빙합니다. TLS 종단·캐시 헤더·다중 사이트가 필요한 경우에만 nginx 추가.
