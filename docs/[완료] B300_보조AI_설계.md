# B300 보조 AI — RAG Q&A · 자동 요약/태깅 (설계)

폐쇄망 B300 GPU에 **생성형 local LLM**을 올려, 외부 AI(MCP·보고서 *작성*)와 구분되는
**시스템 내장 보조 기능**을 구현하기 위한 설계. 첫 두 기능은
**① 아카이브 RAG Q&A**(우리 보고서에게 묻기)와 **② 자동 요약·태깅**(저장 시 백그라운드).

> 토대는 이미 운영 가동 중 — 임베딩·`report_chunks`·하이브리드 검색(`AI_RAG_현황.md`),
> 워커 큐(`백그라운드워커_설계.md`, p47). 본 설계는 그 위에 **생성(generation) 절반**을
> 얹는다. `AI_RAG_현황.md` Phase 3(RAG Q&A)·Phase 4(에이전트: 요약)가 명시한 B300 의존부.
> **상태: 구현 완료.** RAG Q&A(`POST /api/ai/ask`, `app/ai/qa.py`)·엔티틀먼트·자동요약/태깅
> 전부 릴리스됐고, 그 위에 AI 검색 지능화 로드맵 1~7(v0.87~v0.102)까지 얹혔다
> (재랭킹 v0.90 · HyDE v0.91 · 청크 단위 인용 v0.89 · 근거 검증 v0.96 등).
> 아래 "설계 단계·코드 0줄" 서술은 **작성 시점(2026-06) 기준이며 지금은 유효하지 않다** —
> 설계 의도를 읽는 용도로만 보라. (상태 블록 갱신: 2026-07-17)
>
> **잔여(§T·마일스톤 M4):** 운영 1회 캡처 → `glm_chat_response.json` fixture 반입 ·
> 운영팀 확인(인증 Bearer·컨텍스트 길이·동시성 한도·상시 가동) · 자동태그 "적용" UX ·
> `resummarize_all` fan-out 핸들러 · 진단 탭 접근 확대(현재 관리자 전용).

## 0. 한눈에 보기

| 영역 | 내용 | 의존 | 공수(러프) |
|---|---|---|---|
| **L0. LLM 클라이언트 추상화** | `app/ai/llm.py` — backend 토글 `mock`\|`ollama`\|`openai` | 없음 | 2~3일 |
| **E. 접근 제어(엔티틀먼트)** | **선별 유저/조직만 B300 기능 사용** — `AiEntitlement` + 해석·게이트·관리 UI | 권한모델(가동) | 3~4일 |
| **A. RAG Q&A** | 하이브리드 검색 → 컨텍스트 조립 → B300 답변(출처 인용) | L0 + E + 검색(가동) | 1~1.5주 |
| **B. 자동 요약·태깅** | 저장 시 `summarize_report` 잡 → 초록 2~3줄 + 추천 태그 | L0 + E + 워커(가동) | 1~1.5주 |
| **T. 테스트 하니스** | 스텁 서버 · 운영 캡처 fixture · 연결·진단 탭(관리자) · smoke CLI | L0 | 2~3일 |
| **선결** | B300 ↔ 앱서버 네트워크 + 모델 서빙(Ollama/vLLM) | 인프라 | — |

> **E 는 A·B 의 선결 의존**(둘 다 게이트를 통과해야 동작) — 그래서 처음부터 박아넣는다.
> "전원 오픈"으로 만들었다가 나중에 좁히는 건 회귀·누수 위험이 크다.

설계 원칙 (임베딩 레일에서 검증된 패턴을 그대로 복제):
1. **backend 토글 + mock** — B300 없이도 dev 에서 전 파이프라인 검증. `.env` 한 줄로 전환.
2. **안전 degrade** — LLM 미연결/실패해도 검색·저장은 정상. 보조 기능만 조용히 비활성.
3. **권한 재사용** — 새 권한 판정 0개. 검색의 `_visible_scope_ids` / `visible_report_ids`만 사용.
4. **무거운 건 워커로** — 생성은 느리므로 요약은 잡, Q&A 만 동기(또는 SSE 스트리밍).

## L0. LLM 클라이언트 추상화 — `app/ai/llm.py`

`embeddings.py` 와 대칭. 한 함수 `chat(messages, **opts) -> str` 로 통일.

```
env(.env):
    LLM_BACKEND   = ollama | openai | mock      (기본 mock)
    LLM_BASE_URL  = http://<b300-host>:11434    (ollama)  또는  .../v1 (openai 호환)
    LLM_MODEL     = qwen2.5:14b-instruct 등
    LLM_TIMEOUT_S = 120
    LLM_MAX_TOKENS= 1024
```

- **mock** — 입력을 결정적으로 가공해 반환(예: 컨텍스트 첫 문장 + "[mock]"). LLM 없이
  엔드포인트·핸들러·프롬프트 조립·인용 파싱까지 테스트. (현재 기본)
- **ollama** — B300 호스트 Ollama `/api/chat`. bge-m3(임베딩, :11435)와 **별 포트/모델**.
- **openai** — vLLM 등 OpenAI 호환 서버(`/v1/chat/completions`). B300 고성능 서빙 시 유리.
- 실패 시 `LLMError(RuntimeError)` — Q&A 는 502+안내, 요약 핸들러는 예외→큐 재시도.

config.py 추가(기존 embedding_* 옆):
```python
llm_backend: str = Field(default="mock")
llm_base_url: str = Field(default="http://localhost:11434")
llm_model: str = Field(default="qwen2.5:14b-instruct")
llm_timeout_s: float = Field(default=120.0)
llm_max_tokens: int = Field(default=1024)
llm_auto_summarize_on_save: bool = Field(default=False)  # 미배포 환경 보호(embedding_auto_on_save 대칭)
```

## E. 접근 제어 — 선별 유저/조직만 B300 연결

**전원 오픈 금지. 기본 deny.** 시스템 관리자가 *명시적으로 허락한* 사용자/조직만
B300 기능을 쓴다. 파일럿 부서/소수 유저로 시작해 점진 확대하는 길을 처음부터 깐다.

### 왜 별도 모델인가 (User/Workspace 의 bool 컬럼 대신)
- **기능별 분리** — 자동요약은 한 부서 파일럿, RAG Q&A 는 선별 유저… 식으로 따로 연다.
- **subject 통일** — 유저 grant 와 조직(워크스페이스) grant 를 한 테이블에서.
- **감사·되돌림** — `created_by`/`created_at`/`note`, 끄기 = 행 삭제(깔끔).
- 가시성(`grants`)과 **다른 축** — 이건 "데이터를 누가 보나"가 아니라 "이 *기능*을 누가
  쓰나". 섞지 않는다.

### 모델 — `app/ai/models.py` (ReportChunk/ReportSummary 옆)
```
AiEntitlement(
  id PK,
  feature        ENUM('rag_qa' | 'auto_summary' | '*'),   # '*' = 모든 B300 기능
  subject_kind   ENUM('user' | 'workspace'),
  user_id        FK users NULL,          # subject_kind=user
  workspace_slug FK workspaces NULL,     # subject_kind=workspace
  include_descendants BOOL = false,      # 워크스페이스 트리 하위까지(아래 주의)
  enabled        BOOL = true,
  note           TEXT NULL,
  created_by, created_at,
  UNIQUE(feature, subject_kind, user_id, workspace_slug)
)
```
- **`include_descendants` 기본 OFF** — 본부에 grant 줘도 하위 팀에 자동 전파 안 함.
  [[조직간공개]]·게시누수에서 얻은 교훈(상위→하위 자동 전파는 의도치 않은 노출의 단골).
  하위까지 열려면 의식적으로 체크. (조직 트리는 `Workspace.parent_slug`.)
- 마이그레이션 `p50_ai_entitlements`(pgvector 무관 → 단독 배포 가능).

### 해석 — `app/ai/entitlements.py`
```python
def ai_features_for(db, user) -> set[str]:
    """이 사용자가 쓸 수 있는 B300 기능 집합. 빈 set = 권한 없음(기본 deny)."""
    if user.is_system_admin and settings.ai_admin_bypass:   # 기본 true(관리자 테스트용)
        return ALL_FEATURES
    feats = set()
    # 1) 직접 유저 grant
    # 2) 사용자가 멤버인 워크스페이스 grant (+ include_descendants 면 조상 grant 도)
    #    멤버십 = WorkspaceMember + home_workspace_slug
    # '*' 는 ALL_FEATURES 로 확장
    return feats

def ai_enabled_for(db, user, feature: str) -> bool:
    return feature in ai_features_for(db, user)
```
- **personal 워크스페이스**는 유저 grant 로 자연히 커버(개인공간 콘텐츠 = 본인).
- 전역 마스터 스위치와 **AND** — `settings.llm_backend`(mock 이면 사실상 무력) +
  기능별 게이트(`llm_auto_summarize_on_save` 등). 엔티틀먼트는 "누구에게", settings 는
  "기능 자체 on/off". 둘 다 통과해야 동작.

### 게이트 적용점
- **A. RAG Q&A** — 라우트 의존성 `Depends(require_ai_feature('rag_qa'))` → 미권한 403.
- **B. 자동요약** — on-save 트리거에서 `ai_enabled_for(db, author, 'auto_summary')` 일 때만
  `summarize_report` 적재. **작성자(report.created_by) 중심** 판정 — 트리거가 report 를
  쥐고 있고 author 가 안정적(보고서는 여러 게시판에 mount 될 수 있어 워크스페이스 단일
  판정이 모호). "이 사람이 만든 보고서를 요약 대상에 넣을까"가 자연스러운 단위.

### 관리 UI — `ai_settings` 프론트에 "AI 접근" 탭 추가(시스템관리자 전용)
- 기존 `AiSettingsPage`(McpTab/PromptsTab/SkillTab) 옆에 `AccessTab` — 유저/조직 grant
  CRUD(기능 선택, include_descendants 토글, note).
- 백엔드 `app/modules/ai/routes.py` — `Depends(require_system_admin)` 로 보호.

### 프론트 게이팅(기능 숨김)
- `/api/me` 응답에 `ai_features: [...]` 추가(preferences 옆, 본인 응답에만) → UI 가
  미권한 사용자에게 "질문하기" 버튼·AI 패널을 **아예 안 보이게**. 서버 403 은 최종 방어선,
  UI 숨김은 1차.

## A. 아카이브 RAG Q&A — "우리 보고서에게 묻기"

자연어 질문 → 관련 청크 검색 → B300가 **출처를 인용해** 답변. 외부 AI로는 번거로운
전수 본문을 폐쇄망 안에서 대상으로 한다. 데이터가 밖으로 안 나간다.

### 흐름
```
질문 q
  → hybrid_search(db, q, actor, limit=8)            # 권한 게이팅 그대로(검색 재사용)
  → 상위 결과의 청크 본문 수집(report_chunks.text)   # snippet 200자 말고 청크 전문
  → 프롬프트 조립: [1]…[N] 번호 매긴 출처 블록 + 질문
  → llm.chat() → 답변(본문에 [n] 인용)
  → 응답 { answer, citations:[{n, report_id, title, workspace_slug, block_id, page_idx, snippet}] }
```

### 엔드포인트 — `app/modules/reports/routes.py` (검색 옆) 또는 신규 `app/modules/ai/`
```
POST /api/ai/ask    { "query": "...", "limit": 8 }
```
- 워크스페이스 컨텍스트 = 기존 `X-Workspace-Slug`(actor 구성, 검색과 동일).
- **기능 게이트**: `Depends(require_ai_feature('rag_qa'))` → 미권한 403 (§E).
- **데이터 권한**: `hybrid_search` 가 이미 `_visible_scope_ids` 로 게이팅 → **추가 권한 코드 0**.
  답변·인용은 사용자가 못 보는 보고서를 인용할 수 없다(검색 결과만 컨텍스트로).
  → 두 축이 직교: §E 는 "기능 사용 가능 여부", 검색 게이팅은 "어떤 보고서를 근거로".
- **근거 없음 가드**: 검색 0건 또는 최고 score < 임계 → LLM 호출 없이
  "관련 보고서를 찾지 못했습니다" 반환(환각 방지). 임계는 `embedding_hybrid_min_score` 재사용/별도.
- (선택, 2차) SSE 스트리밍 — 첫 토큰 지연 체감 완화. MVP 는 동기 JSON.

### 프롬프트 골격(요지)
```
시스템: 당신은 사내 CAE 보고서 아카이브 어시스턴트다. 아래 [출처]만 근거로,
        한국어로 간결히 답하고 각 주장 끝에 [번호]로 인용하라. 출처에 없으면
        "해당 내용은 아카이브에서 찾지 못했습니다"라고 답하라. 추측 금지.
[출처]
[1] (보고서: <title>) <청크 본문>
[2] ...
질문: <q>
```
- 컨텍스트 길이 가드: 청크 N개 × 길이 상한으로 토큰 폭주 방지(모델 컨텍스트에 맞춤).
- 인용 파싱: 답변 텍스트의 `[n]` 토큰을 citations 의 n 과 매칭해 프론트가 클릭→보고서 이동.

### 프론트(가벼움)
- 검색 페이지/사이드패널에 "질문하기" 입력 + 답변 카드(인용 칩 → `/w/{slug}/reports/{id}`).
- mock 백엔드(dev)에선 답변 품질 검증 불가 → 실 B300 가동 후 UI 마감(검색 시맨틱 토글과 동일 전략).

## B. 자동 요약 + 자동 태깅 (저장 시 백그라운드)

사람이 안 봐도 되는 **완전 자동·투명** 기능. 저장 시 이미 `embed_report` 잡이 뜨는
바로 그 chokepoint에 `summarize_report` 잡을 나란히 적재한다. 검색 패싯·대시보드·
(향후)다이제스트를 전부 강화하는 토대.

### 저장 (mirror `ReportChunk`) — `app/ai/models.py`
1:1 `ReportSummary`(report 당 1행). content_hash + 모델 지문으로 unchanged-skip.
```
ReportSummary(report_id PK/FK, summary TEXT, tags JSONB,
              suggested_category TEXT NULL, content_hash, model, updated_at)
```
- 마이그레이션: 체인 `… → p48_report_chunks → p49_report_summaries`(pgvector 무관).
- **AI 태그는 "추천"** — 사람이 확정한 분류(`section_taxonomy`)를 덮어쓰지 않는다.
  UI 에서 칩으로 노출 → 사용자가 "적용" 클릭 시에만 실분류/검색 패싯에 반영.

### 핸들러 — `app/jobs/handlers/summarize_report.py` (`embed_report` 대칭)
```python
@handler("summarize_report")
def summarize_report(session, payload):
    report = session.get(Report, report_id)
    # 소프트삭제 → 기존 요약 제거 후 종료(검색 누수 방지, embed_report 와 동일 규약)
    text = extract_searchable_text_for_report(report)          # 기존 추출 재사용
    fingerprint = f"{settings.llm_backend}:{settings.llm_model}"
    content_hash = sha256(fingerprint + text)
    if 기존.content_hash == content_hash and not force: return {"skipped": "unchanged"}
    out = llm.chat(SUMMARIZE_PROMPT(text))   # JSON 강제: {summary, tags[], category?}
    upsert ReportSummary(...)                # 실패 시 LLMError → 큐 재시도
```
- 프롬프트는 **JSON 출력 강제**(요약·태그·분류) → 파싱. 형식 깨지면 예외→재시도, N회 후
  요약 없이 종료(저장은 이미 끝났으므로 무해).
- 비용 가드: `content_hash` 로 본문 무변경 저장은 LLM 호출 skip(embed 와 동일).

### 트리거 — `reports/models.py` `after_commit` 확장
기존 `_enqueue_report_embeddings` 바로 옆에서 같은 `_reports_to_embed` 버킷을 활용해
`summarize_report` 도 적재(`dedup_key=f"summarize:{rid}"`). **두 게이트 AND**:
① `settings.llm_auto_summarize_on_save`(전역 on/off — 임베딩과 독립, B300 미연결 시 요약만 끔)
② `ai_enabled_for(db, author, 'auto_summary')`(§E — 작성자 엔티틀먼트). 둘 다여야 적재.

### 활용처(요약·태그가 떠받치는 것)
- 보고서 카드/목록의 **자동 초록**(지금은 사람이 요약 안 쓰면 빔).
- 검색 패싯·`section_taxonomy` 추천(부족한부분.md §빠른보완 "자동태깅").
- 대시보드/다이제스트, 종합보고 그룹 요약의 씨앗.

## 운영·안전

- **선결**: B300 ↔ 앱서버 네트워크(방화벽) + 모델 서빙 결정(Ollama 간편 / vLLM 고throughput).
  임베딩(:11435)과 **포트·프로세스 분리**(GPU 메모리·모델 다름).
- **degrade 매트릭스**: `llm_backend=mock` 또는 호출 실패 시 — Q&A 는 안내 메시지,
  자동요약은 잡 재시도 후 조용히 패스. **검색·저장·임베딩은 전혀 영향 없음**.
- systemd: 요약은 워커(가동 중)가 처리 — 새 유닛 불필요. Q&A 는 웹 프로세스 동기 호출.
- **부하**: 자동요약 = 저장당 1콜(unchanged-skip 으로 실질 적음). reindex 대량 1회는
  `reindex_embeddings` 처럼 `resummarize_all` fan-out 핸들러로(선택).

## T. 테스트 환경 — dev 에서 B300 없이 개발·검증

**제약**: dev 서버는 B300(10.198.143.137:10000)에 못 닿는다. **오직 운영 서버만** 닿는다.
B300 는 OpenAI 호환(`/v1/chat/completions`, 모델 `GLM-5-2`, `chat_template_kwargs.reasoning_effort`)
→ §L0 의 `openai` 백엔드 경로. 따라서 **모든 테스트 GUI·스모크는 브라우저가 아니라 *서버* 가
B300 를 호출**하는 구조여야 한다(브라우저 직접 호출은 운영에서도 네트워크/CORS 로 막힘).

### 4계층 + 운영 1회 캡처
1. **mock** (§L0) — 네트워크 0. 프롬프트 조립·인용 파싱·엔티틀먼트 게이트·잡 흐름. 결정적.
2. **로컬 OpenAI 호환 스텁** — `scripts/llm_stub.py`(FastAPI): `/v1/models` + `/v1/chat/completions`
   를 **GLM-5.2 와 같은 응답 모양**으로 반환(아래 캡처 fixture 재생 또는 echo). `LLM_BACKEND=openai`,
   `LLM_BASE_URL=http://localhost:<port>/v1` 로 겨눠 **실 `openai` 어댑터(httpx·바디·파싱·타임아웃)**
   를 B300 없이 실행. 자동테스트는 httpx `ASGITransport` 로 포트 없이 인-프로세스, 수동 UI 는 포트로.
3. **(선택) 작은 실모델** — 기존 임베딩용 Ollama 로 `ollama pull qwen2.5:3b`. Ollama 가
   `/v1/chat/completions` 지원 → 답변/요약 "품질 감". 단 `reasoning_content`·`chat_template_kwargs`
   는 GLM 과 달라 "모양" 아닌 "느낌"용.
4. **운영 1회 캡처 → fixture 반입**(.deb 반입 경로 재사용). 운영 접근자가 아래 2줄 실행 →
   응답 JSON 을 `backend/tests/fixtures/glm_chat_response.json` 로 저장 → 스텁이 재생 →
   dev 에서도 **진짜 응답 모양**(특히 `reasoning_content` 분리 여부·`usage`)에 파싱 핀 고정.
   ```bash
   curl -s http://10.198.143.137:10000/v1/models
   curl -s http://10.198.143.137:10000/v1/chat/completions -H "Content-Type: application/json" \
     -d '{"model":"GLM-5-2","messages":[{"role":"user","content":"한 문장 요약 테스트"}],"temperature":1,"max_tokens":4096,"chat_template_kwargs":{"reasoning_effort":"high"}}'
   ```

### 연결·진단 탭 — `ai_settings` AiSettingsPage 신규 탭
- 기존 McpTab/PromptsTab/SkillTab + AccessTab(§E) **옆에** "연결·진단" 탭.
- **접근: 일단 시스템 관리자 전용**(AiSettingsPage 가 이미 require_system_admin 게이팅 — 추가
  권한 코드 0). 추후 부서 매니저 등으로 넓힐 여지는 남기되 지금은 관리자만.
- 구성: ① 백엔드 상태 카드(backend/base_url/model + [연결 테스트]) ② 프롬프트 플레이그라운드.
- 엔드포인트 `app/modules/ai/routes.py`, **둘 다 `Depends(require_system_admin)`**:
  - `POST /api/ai/diag/ping` — 서버가 `/v1/models` + 짧은 chat → `{ok, latency_ms, model, has_reasoning, raw}`.
  - `POST /api/ai/diag/chat` — 임의 프롬프트 → `llm.chat` 원응답(content + reasoning + usage + latency).
- **이 탭 = dev 스텁 검증 + 운영 실연결 스모크 + 상시 헬스체크**(서버 경유라 운영 관리자가
  브라우저에서 누르면 곧 운영 스모크). 임베딩 가동확인하던 것처럼 상주.

### smoke CLI — `scripts/llm_smoke.py`
브라우저 없이(SSH·크론) 운영에서 빠르게 찌르는 헤드리스판. 진단 탭과 같은 `llm.chat` 호출.

### 어댑터 관대성(캡처 전에 짜기 위한 핵심)
`openai` 어댑터는 응답 모양에 **관대**해야 한다 — `message.content` + (있으면)`message.reasoning_content`
분리·스트립, `usage` 유무 무관. 그래야 캡처 전 스텁으로 먼저 만들고, 캡처 후 fixture 로 핀 고정.

### 운영팀 확인 항목(캡처로 안 나오는 것)
인증(Bearer 키 필요?) · 컨텍스트 길이(`max_model_len` → RAG 청크 예산) · 공유/동시성 한도
(자동요약 fan-out 보호) · 상시 가동 여부(Q&A 동기 vs 요약 백그라운드) · **임베딩은 B300 아님**
(생성 전용, 임베딩은 기존 Ollama bge-m3 :11435 유지).
