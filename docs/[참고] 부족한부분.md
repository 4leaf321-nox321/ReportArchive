
  🔴 가장 큰 공백 (효과 큼)

  1. 알림 전달 (이메일 + 실시간)
  - 지금은 in-app 알림만 있고 SMTP·실시간(WS/SSE)이 없음 → 코멘트, 공유, 종합보고 제출/승인, 게시 같은 걸 앱을 안 열면 모름. 비번 분실도 그래서 관리자 중개죠.
  - 제안: 이메일/사내 메신저 웹훅 발송 + 보드/폴더/보고서 "팔로우→알림", 일일 다이제스트.

  ▸ 핵심: 어려운 건 코드가 아니라 "무엇으로 보낼지(발송 채널)" = 인프라/사내 승인.
    - SMTP = 이메일을 배달해주는 "우체국 서버". 우리 앱은 혼자 메일을 못 보내고, 이 우체국에 맡겨야 배달됨.
    - SMTP 서버를 직접 만들 필요 없음(오히려 어렵고 비권장): 자체 서버 메일은 스팸 처리/거부되고, 사내망은 공식 메일서버만 외부 발송 허용. → 회사에 이미 있는 메일 서버(릴레이)를 빌려 쓰는 게 정석.
  ▸ 준비 사항(나중에 착수) — IT에 받아올 값:
    1) 릴레이 서버 주소 + 포트 (예: mailrelay.사내 : 25 또는 587)
    2) 인증 필요 여부 (없음=IP 허용 / 아이디·비번 / 토큰)
    3) 암호화(TLS/STARTTLS) 사용 여부 + 포트
    4) 발신 주소(From) 무엇으로 가능 — 보통 승인된 주소/도메인만 (예: no-reply@부서.samsung.com)
    5) 우리 앱 서버 IP가 릴레이 사용 허용(방화벽)됐는지
    6) 사외 발송 가능 여부 / 발송량 제한
    · IT 질문 한 줄: "앱 서버에서 사내 사용자에게 알림 메일을 보내려는데, 사용할 사내 SMTP 릴레이 주소/포트와 인증 필요 여부를 알려달라."
  ▸ 코드 쪽 접근(요청 막지 않고 유실 방지): 발송 추상화(MAIL_BACKEND = noop|smtp|webhook, 기본 noop) + outbox 테이블(기존 notifications 재사용) + 드레이너(재시도) + 사용자 환경설정(User.preferences 재사용: 이벤트별 on/off·즉시/다이제스트). 다이제스트는 systemd 타이머로.
    · 채널 확보가 늦으면 사내 메신저 Incoming Webhook 우선이 더 쉬울 수 있음.

  2. 계정 연동(SSO) + 2단계 인증
  - 현재 비밀번호 + 관리자 중개 복구뿐. 사내(samsung.com) 환경이면 AD/SSO(SAML/OIDC)·2FA가 사실상 필수.
  - 제안: SSO 로그인, 2FA, 세션 강제 종료(접속이력과 연계 — "이 세션 로그아웃").

  ▸ 삼성 Knox Portal 연동 — 먼저 "어떤 방식인지" 파악이 출발점. 보통 셋 중 하나:
    - OIDC/OAuth2 (요즘 표준, 가장 다루기 쉬움)
    - SAML 2.0 (전통 사내 SSO)
    - 게이트웨이 헤더 주입형 (앞단이 인증하고 사용자 정보를 HTTP 헤더로 전달)
  ▸ 준비 사항(나중에 착수) — IT/Knox 문서에서 받아올 것:
    1) 연동 프로토콜이 뭔지 (OIDC / SAML / 헤더형)
    2) 앱(클라이언트) 등록 절차 — 누가 승인, 무엇을 발급(OIDC: client_id/secret, SAML: IdP 메타데이터 XML+인증서)
    3) 엔드포인트:
       - OIDC면 "/.well-known/openid-configuration" 한 줄이면 나머지(authorize/token/userinfo/공개키)가 다 들어있음 → 이것부터 요청
       - SAML이면 IdP 로그인 URL, 메타데이터, NameID 형식
    4) 콜백(redirect) URL 등록 — 우리 앱 복귀 주소를 허용 목록에 추가
    5) 돌려주는 사용자 정보(클레임): 이메일·사번(고유 ID)·이름·부서 → User 매칭 키 결정
    6) 테스트 환경/계정 제공 여부
    7) 우리 서버에서 Knox 엔드포인트로 네트워크 연결 가능한지(방화벽)
    · IT 질문 한 줄: "이 앱을 Knox Portal로 SSO 연동하려는데 OIDC인지 SAML인지, (OIDC면) discovery URL과 앱 등록 방법을 알려달라."
  ▸ 미리 결정해 둘 것:
    - SSO 로그인과 기존 비밀번호 로그인을 병행할지/대체할지
    - 첫 SSO 로그인 시 자동 계정 생성(JIT)할지, 사전 등록자만 허용할지
    - 계정 매칭 키 = 사번(권장, 이메일은 바뀔 수 있음) vs 이메일
  ▸ 코드 쪽: 프로토콜 확정 후 OIDC(authlib)나 SAML(python3-saml) 골격 + 콜백 라우트 + 계정 매칭/자동생성. 값만 꽂으면 켜지도록 기능 플래그로 미리 깔아둘 수 있음.

  3. 실시간 공동 편집 / 프레즌스
  - 지금은 edit-lock 방식이라 동시 편집 불가(한 명이 잠그면 대기).
  - 제안: 최소 "누가 보고 있음/편집 중" 프레즌스 + 셀/위젯 단위 잠금, 이후 동시 편집.

  🟡 도메인(CAE/엔지니어링) 특화 기회

  4. 해석 데이터 연동 / 역임포트
  - 위젯은 풍부하지만 데이터는 수기 입력. CAE 결과 파일·CSV/엑셀에서 표·차트 자동 생성, 엑셀/PPT를 보고서로 역임포트, (장기) 라이브 데이터 위젯.

  5. 추세·KPI 대시보드
  - 종합보고는 보고서 "모음"이지 분석이 아님. 주차별 보고서의 수치 위젯(응력·안전계수 등)을 가로질러 추세/KPI로 집계하는 대시보드 + 엔티티/BOM 마스터(모델↔부품↔보고서) 강화.

  🟢 워크플로 · 거버넌스

  6. 결재/승인 워크플로 — 단계·승인자·기한·리마인더(RACI 위젯은 표시일 뿐 엔진 없음).
  7. 감사·보존 — 활동/접속 로그는 있으나 보존정책·로그 내보내기, 보고서 만료/아카이빙.

  🔵 빠른 보완 (기존 자산 재사용, 비용↓)

  - 공개 공유 링크(만료·읽기전용) — cross-org view 자산 확장.
  - 예약/일괄 내보내기(스케줄러 없음), PPT 폰트 임베드(현재 치환 위험), 모바일 읽기 뷰(데스크톱 그리드 위주).
  - 검색 패싯(부서·종류·기간·작성자·태그) + 저장된 검색.
  - AI 확장: 아카이브 RAG Q&A·보고서 자동요약/자동태깅·수치 이상치 탐지(이미 MCP 기반이 있어 비교적 가까움).
