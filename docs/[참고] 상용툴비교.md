# ReportArchive vs Notion vs Confluence — 장단점 비교

세 플랫폼은 같은 카테고리("문서/협업 도구")로 묶이지만 실제로는 서로 다른
시장을 겨냥하고 있다. 이 문서는 각 플랫폼의 포지셔닝, 영역별 강약, 그리고
ReportArchive 가 어디에 위치하는지를 정리한다.

---

## 한 줄 정체성

| 플랫폼 | 포지셔닝 |
|---|---|
| **Notion** | All-in-one 워크스페이스 — 노트 · DB · 위키 · 프로젝트 관리를 한 도구에서 |
| **Confluence** | 엔터프라이즈 위키 — 팀 지식 베이스 + Atlassian (Jira) 생태계 |
| **ReportArchive** | 보고서 작성 특화 플랫폼 — 시각화 · 도메인 위젯 · AI 생성 |

---

## 영역별 비교

| 영역 | Notion | Confluence | ReportArchive |
|---|---|---|---|
| **전체 블록/위젯 수** | ~50 | 50+ 공식 / 1000+ marketplace | **33** |
| **시각화 위젯** | ~2 (DB view 통계 정도) | ~5 + 외부 app 의존 | **17** ⭐ |
| **데이터베이스 view** | **매우 강** (table/board/gallery/calendar/timeline) ⭐ | 약 | 없음 |
| **인라인 협업** (멘션·코멘트·실시간) | **매우 강** ⭐ | 강 | 약 |
| **외부 통합 / 임베드** | 강 (네이티브 다수) | **매우 강** (marketplace) ⭐ | 약 (html_embed 만) |
| **위키 / 계층 구조** | 강 (중첩 페이지) | **매우 강** (space, 계층) ⭐ | 보고서 단위 |
| **도메인 특화** | 약 (general purpose) | 약 (Atlassian 중심) | **강** (CAD, equation, RACI, 프레임워크) ⭐ |
| **AI 통합** | 강 (Notion AI) | 약 (Atlassian Intelligence 도입 중) | **강** (위젯 자동 생성) |
| **권한 / 감사** | 중 | **매우 강** (엔터프라이즈) ⭐ | 기본 |
| **UI/UX** | 매우 친화적 | 무겁고 구식 | 보고서 작성에 최적화 |
| **자체 호스팅** | 불가 (SaaS) | 가능 (Data Center) | **가능** |
| **가격 모델** | freemium → 유료 | 유료 (subscription) | 자체 운영 |

## Notion

### 장점
- **데이터베이스 view 패러다임** — 한 데이터를 table / board / gallery / calendar / timeline 으로 자유롭게 변환. 경쟁사 어디도 따라잡지 못하는 핵심 차별점
- **풍부한 텍스트 / 구조 블록** — 15+ 종의 텍스트 블록 (callout, toggle, sync block, mention, breadcrumb, TOC 등)
- **실시간 협업** — 동시 편집, 멘션, 코멘트, 알림이 매끄럽게 연동
- **임베드 카탈로그** — Figma, Loom, Google Drive, GitHub gist, Codepen, Twitter, Maps 등 30+ 네이티브 임베드
- **사용자 친화적 UI** — 학습 곡선이 낮고 모바일까지 일관
- **Notion AI** — 문서 안에서 직접 AI 호출, 요약/번역/작성

### 단점
- **시각화가 거의 없음** — 차트는 사실상 부재. DB view 의 간단한 통계가 전부, 진짜 차트는 외부 서비스 (charts.notion.so 등) embed 의존
- **도메인 특화 부재** — 모든 게 general-purpose. 수식, CAD, 전략 프레임워크 같은 specialized 위젯 없음
- **복잡한 보고서 layout 한계** — 페이지 = 위에서 아래로 흐르는 컬럼 구조. 인쇄/PPT 같은 정밀 레이아웃 어려움
- **엔터프라이즈 기능 약함** — SSO, 감사 로그, 세밀한 권한이 일정 수준 이상 enterprise tier 에서만, 그마저도 Confluence 대비 부족
- **자체 호스팅 불가** — 모든 데이터가 Notion 서버. 보안 민감 조직엔 채택 어려움
- **export 제약** — Markdown / PDF export 가 있지만 layout 손실, 재import 안 됨

## Confluence

### 장점
- **엔터프라이즈 위키 구조** — Space → 페이지 계층, 권한 상속, 페이지 history / restore / compare 가 견고
- **Atlassian 생태계 연동** — Jira issue 임베드, Bitbucket repo 링크가 1차 시민. 개발 조직과의 자연스러운 통합
- **Marketplace 1000+ apps** — Draw.io, Gliffy, PlantUML, 차트 plugin 등 무엇이든 추가 가능
- **엔터프라이즈 권한 / 감사** — SSO, SAML, 감사 로그, 데이터 거주지 통제 등 컴플라이언스에 강함
- **Data Center 자체 호스팅** — 폐쇄망 / 보안 민감 조직에 적합
- **장기 안정성** — 20년 가까운 운영 이력, 대기업 / 정부 도입 사례 풍부

### 단점
- **UI/UX 가 무겁고 구식** — Notion / 최신 도구 대비 응답성·인터랙션이 명백히 뒤떨어짐
- **시각화 / 차트가 약함** — Atlassian 자체 차트 macro 는 빈약. 좋은 시각화는 모두 marketplace 유료 app
- **인라인 협업이 Notion 보다 약함** — 코멘트 thread / 멘션은 있지만 실시간 동시 편집 경험이 떨어짐
- **데이터베이스 view 없음** — 단순 table macro 만 존재
- **좋은 기능 대부분 marketplace 유료** — 라이선스 누적 비용이 무시 못 함
- **검색 / 탐색 느림** — 대규모 space (수만 페이지) 에서 검색 품질 / 속도 모두 약점
- **모바일 경험 빈약**

## ReportArchive

### 장점
- **시각화 위젯 라인업이 압도적** — 17개의 차트·다이어그램. Notion 의 약 8배, Confluence 기본 macro 의 3배
  - 좌표 차트 8: chart, scatter, scatter3d, radar, box, density, heatmap, contour
  - 비율 4: pie, waffle, treemap, packing
  - 흐름/관계 5: flowchart, tree, mind_map, sankey, network
- **도메인 특화 위젯** — 일반 SaaS 에 없는 위젯: CAD 3D viewer, LaTeX equation, RACI matrix, milestone tracker, comparison 매트릭스, 2x2 quadrant (SWOT/BCG/Eisenhower)
- **AI 자동 생성 워크플로** — `widgetExamples.js` 카탈로그 기반으로 AI 가 위젯 + 데이터를 직접 채워 보고서 초안 생성
- **보고서에 특화된 레이아웃** — PPT 슬라이드 가이드, auto-fit / square cell, fullscreen viewer, RGL 드래그 등 보고서 작성/발표에 최적화
- **자체 호스팅 가능** — 데이터 완전 통제. 보안 민감 / 폐쇄망 조직 친화
- **위젯 컨텐츠 모델 일관성** — 모든 위젯이 `props (template)` + `content (per-report)` 분리, AI / 사용자 둘 다 같은 모델로 작업
- **수식 / 3D 모델 / 전략 프레임워크** 같은 specialized 콘텐츠 — 엔지니어링/분석/전략 보고서에 즉시 활용 가능

### 단점
- **인라인 협업 부재** — 코멘트, 멘션, 실시간 동시 편집 모두 없음 (현재 약점 1순위, 별도 로드맵에서 다룸)
- **데이터베이스 / view 패러다임 없음** — 데이터를 한 곳에 두고 여러 view 로 보는 Notion DB 같은 구조 부재
- **외부 서비스 임베드 카탈로그 얇음** — `html_embed` 하나로 모든 임베드 처리, Figma / Loom / Google Sheets 같은 이름 있는 임베드 위젯 없음
- **위키 / 페이지 계층 구조 약함** — 보고서 단위 모델이라 대규모 지식 베이스로는 부적합
- **엔터프라이즈-grade 권한 / 감사 미흡** — SSO, 세밀한 권한, 감사 로그 부족
- **모바일 / 협업 알림 인프라 없음** — 데스크탑 보고서 작성 도구에 가까움
- **인지도 / 생태계** — 신생 플랫폼이라 marketplace · 커뮤니티 · third-party 통합 없음

## 어떤 사용 사례에 어떤 플랫폼인가

| 사용 사례 | 최적 플랫폼 | 이유 |
|---|---|---|
| **분석 / 기술 / 전략 보고서** (그래프 多, 1회 발행성) | **ReportArchive** | 시각화 + 도메인 위젯 + 보고서 layout |
| **엔지니어링 / R&D 문서** (수식, CAD, 다이어그램) | **ReportArchive** | equation, cad_3d, network 등 specialized 위젯 |
| **컨설팅 산출물** (SWOT, BCG, RACI, 비교 매트릭스) | **ReportArchive** | quadrant, raci_matrix, comparison 등 프레임워크 위젯 |
| **팀 위키 / 지식 베이스** (수천 페이지, 권한 계층) | **Confluence** | space 구조, 권한, history, 엔터프라이즈 기능 |
| **개발 조직 문서화** (Jira / Bitbucket 연동) | **Confluence** | Atlassian 생태계 연동 |
| **개인/팀 노트 + 프로젝트 관리** | **Notion** | DB view (kanban/calendar/list) + 협업 UX |
| **회사 핸드북 / 정책 위키** | **Notion** or **Confluence** | 협업 inline + 페이지 계층 |
| **실시간 협업 작업 문서** | **Notion** | 매끄러운 동시 편집 + 멘션 |
| **데이터 dashboard** | 셋 다 부적합 | BI 전용 도구 (Tableau, Power BI, Looker, Superset) |

## ReportArchive 의 차별화 포지셔닝

ReportArchive 는 **"보고서 작성에 특화된 시각화-rich 플랫폼"** 으로,
일반 wiki / 문서툴 (Notion / Confluence) 과 BI 전용툴 (Tableau / Power BI) 의
중간 niche 를 차지한다.

```
[일반 문서 / 위키]              [보고서 특화]              [BI / Dashboard]
Notion / Confluence  ←  ReportArchive (니치)  →  Tableau / Power BI
- 텍스트 · 협업 강함     - 시각화 · 도메인 위젯 강함    - 데이터 분석 강함
- 시각화 약함            - 협업 약함                   - 본문 / 협업 약함
- 도메인 특화 약함       - 위키 계층 약함              - 발표 / 보고서 약함
```

### 강점을 더 강화할 영역
- 시각화 위젯은 이미 상용 평균 압도 — 추가는 한계 효용 작음
- 도메인 특화 위젯 (RACI, Quadrant 등) — 컨설팅 / 엔지니어링 시장의 명확한 차별점
- AI 보고서 자동 생성 — 다른 두 플랫폼이 따라오기 어려운 영역

### 격차를 좁혀야 할 영역 (자세한 로드맵은 `약점보강_로드맵.md`)
- **협업 inline** — 인라인 코멘트가 우선순위 1순위, 1-2주 작업으로 가장 큰 ROI
- **이름 있는 임베드 위젯** — Figma / Loom / Google Sheets 등 5-7개 추가로 통합 격차의 60% 즉시 해소
- **데이터베이스 view 패러다임** — 도입 여부는 "워크스페이스 툴로 확장할 것인가" 의 큰 방향 결정 후

### 들어가지 말아야 할 영역
- **범용 노트 / 모바일 협업** — Notion 의 영토. 따라잡으려면 정체성 흐려짐
- **엔터프라이즈 위키 / 권한** — Confluence 의 영토. 별도 시장
- **BI dashboard** — Tableau / Power BI 의 영토. 보고서 ≠ live dashboard
