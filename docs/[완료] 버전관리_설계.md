# 보고서 수정 이력·되돌리기(버전 관리) 설계 · 진행 체크리스트

보고서 본문의 과거 상태를 **보기 / 비교 / 되돌리기**. 협업 편집(편집권 인계·잠금)
환경에서 실수 덮어쓰기·잘못된 편집을 복구하는 안전망. **비용(스토리지) 설계가 핵심.**

## 0. 조사로 드러난 핵심 사실 (설계 전제)

- **자동저장 없음 — 수동 "저장"만.** 저장은 편집 세션당 몇 번뿐 → 스냅샷 빈도가 본래 낮다(최대 비용 리스크가 이미 완화). `update_report`(services.py)가 유일 저장 경로, 매 저장 `revision +1`.
- **편집 잠금**(ReportEditLock, TTL 120s) 으로 "편집 세션" 경계 식별 가능.
- 본문 = `reports.pages` JSONB(+레거시 content/overrides). 보통 수십~수백 KB, Postgres가 TOAST 자동 압축.
- 권한: `can_read_report`(보기)·`can_edit`(편집/되돌리기) 헬퍼 재사용.
- `ReportActivityType.edited` enum 존재하나 미사용 → 스냅샷 시 같이 기록.
- 프론트: 더보기(⋯) 메뉴에 "활동 이력"·`ActivityTimeline.jsx`·`InlineReportView`(스냅샷 읽기전용 렌더) 가 있어 **버전 UI에 그대로 재사용**.

## 1. 비용 설계 (★ 가장 중요)

스토리지 비용 = **버전 수 × 버전당 크기**. 둘 다 누른다. 영향 큰 순서:

### (A) 버전 수 — 저장마다 1버전 + 무변경 dedup  (★시간 병합 폐기)
- **저장 한 번 = 복원점 하나.** (초기 설계의 "세션 병합(10분)"은 *폐기* — 수동저장에선
  저장 한 번 한 번이 의도한 체크포인트인데, 병합이 같은 세션의 위젯 삭제 같은 변경을
  지워 "방금 실수 되돌리기"를 막았다. 사용자 결정: 구조든 내용이든 저장마다 남긴다.)
- **무변경 dedup:** 본문 sha256 저장. 직전 버전과 해시가 같으면(중복 저장) **건너뜀**.
- **폭증 방지는 (C) prune(보고서당 최근 20)** 가 담당 — 수동저장이라 빈도 낮고, gzip+상한으로
  보고서당 ~1MB 미만. (자동저장이 나중에 생기면 그땐 prune 개수·짧은 dedup 윈도우 재검토.)

### (B) 버전당 크기 줄이기 — gzip BYTEA 저장
- 스냅샷은 **통째로 읽고 쓰는 불투명 blob**(안을 SQL 질의할 일 없음) → JSONB 대신 **gzip 한 JSON 텍스트를 `bytea`** 로 저장. JSON 텍스트 기준 ~5–10x 압축 + JSONB 파싱 오버헤드 제거.
- 표시·정렬용 메타(작성자·시각·revision·원본 바이트수)만 별도 컬럼.

### (C) 보존 정책 — 총량 상한 (prune)
- 보고서당 **최근 N개(기본 20)** 유지. 삽입 직후 동기 prune(초과분 삭제).
- **항상 보존:** 게시(finalized) 시점 버전, 명명 체크포인트(`is_pinned`), **되돌리기 직전 자동 스냅샷**.
- (후순위) 계층 thinning: 7일내 전체 → 30일 1/일 → 그 이후 1/주.

### (E) 미디어는 참조만 — 버전이 동영상/이미지를 복제하지 않음
- 동영상·이미지·첨부·CAD는 본문 JSON이 아니라 업로드 폴더에 파일로 저장되고, content엔
  `file_id` 참조(수십 바이트)만 들어간다. → **스냅샷 크기는 미디어 용량과 무관**(1GB 동영상이어도
  버전당 수십 KB). 보존 N은 KB 단위 본문만 곱한다. 미디어 바이트는 업로드 폴더에 1회 저장·공유.
- **단, 현재 자동 파일 GC 없음** — 옛 버전이 참조하는 파일이 그대로 살아 있어 미리보기/되돌리기가
  깨지지 않음. **향후 미참조 파일 GC를 넣을 땐 반드시 'version-aware'**(버전 참조도 카운트)로 해야
  옛 버전이 안 깨진다.

### (D) 콜드 분리
- 별도 테이블 `report_versions`(핫 `reports` 와 분리). FK CASCADE(보고서 삭제 시 함께). 향후 **별도 테이블스페이스/디스크**로 이전 가능(콜드 데이터) — DB 디렉토리 이전 논의와 연결.

### 대략 비용 감 (정당화)
- 수동저장 + 세션병합 → 활발히 편집되는 보고서도 하루 1~수 버전, 대부분 보고서는 드묾.
- gzip 스냅샷 ~10–40KB, 최근 30개 유지 → **보고서당 ~0.3–1.2MB**. 5,000건이라도 worst ~수 GB(실제론 훨씬 적음), prune 으로 상한.
- → **diff 저장은 채택 안 함**(복원 복잡·취약, 대형 재구성엔 이득 적음). full+gzip+세션병합+prune 조합이 단순·견고하면서 충분히 저렴.

## 2. 되돌리기(restore) 의미론

- **비파괴적:** 되돌리기 = 그 버전의 본문을 **새 저장으로 적용**(revision +1). 현재 상태는 절대 안 잃음(git revert 식, reset 아님).
- 되돌리기 직전 **현재 상태를 자동 스냅샷**(되돌리기 자체도 되돌릴 수 있게).
- 권한 `can_edit` + **편집 잠금 필요**(동시 편집 충돌 방지). 보기/미리보기는 `can_read_report`.
