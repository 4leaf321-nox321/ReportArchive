# 배포방법 (최종)

3대 컴퓨터 흐름으로 폐쇄망 서버에 배포한다.

```
[개발 컴퓨터]        [GitHub Actions]            [중간 윈도우]              [폐쇄망 리눅스 서버]
 git push       →   번들 자동 빌드        →     .tar.gz 다운로드       →    deploy.sh (한 스크립트)
 git tag             Release에 첨부             scp로 서버에 전송
```

서버 측은 **모든 작업이 `deploy.sh` 하나**로 통일됨 — install / update / reset / status가 같은 스크립트의 서브커맨드.

---

## 빌드는 언제 자동으로 도나

| 액션 | GitHub Actions가 빌드함? | 결과물 |
|---|---|---|
| `git push` (평소 커밋) | ❌ | 없음 (코드만 GitHub에 올라감) |
| `git push origin v0.2.0` (태그 push) | ✅ | Releases에 `.tar.gz` 자동 첨부 |
| Actions 탭에서 "Run workflow" 클릭 | ✅ | Artifacts에만 업로드 (Release 안 만듦) |

평소 작업은 그냥 `git push` — 빌드 안 됨. **배포 시점에만 태그를 새로 찍는다**.

```bash
# 평소 — 빌드 안 함
git add -A && git commit -m "..."
git push

# 배포 — 이때만 번들이 만들어짐
git tag v0.2.0
git push origin v0.2.0
```

## A. 처음 세팅 (한 번만)

### A-1. 개발 컴퓨터 — 첫 번들 트리거

```bash
git tag v0.1.0
git push origin v0.1.0
```

→ 10분쯤 뒤 Releases에 `reportarchive-v0.1.0.tar.gz` 첨부.
진행: `https://github.com/4leaf321-nox321/ReportArchive/actions`

### A-2. 중간 윈도우 — 다운로드 + scp 전송

**1) Releases 페이지에서 `.tar.gz` 다운로드**

```
https://github.com/4leaf321-nox321/ReportArchive/releases/latest
```

다운로드된 파일은 보통 `%USERPROFILE%\Downloads\reportarchive-v0.1.0.tar.gz` 에 떨어진다.

**2) PowerShell 열고 scp 명령 실행**

```powershell
scp $env:USERPROFILE\Downloads\reportarchive-v0.1.0.tar.gz user@서버IP:/tmp/
```

| 토큰 | 무엇 |
|---|---|
| `$env:USERPROFILE\Downloads\…` | 윈도우 측 원본 파일 (절대 경로). 다른 곳에 받았으면 그 경로. |
| `user` | 운영 서버에 ssh 가능한 계정 (예: `ops`, `deploy`, `<운영자ID>`) |
| `서버IP` | 운영 서버 IP 또는 호스트명 (`192.168.x.x` 등) |
| `/tmp/` | 서버 측 도착 디렉터리. `/tmp` 가 풀기 좋고 권한 문제 적음. |

**처음 접속할 때 한 번만 뜨는 경고**

```
The authenticity of host '192.168.x.x' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no)?
```
`yes` 엔터 → 서버 host key 가 `%USERPROFILE%\.ssh\known_hosts` 에 등록됨. 다음부터는 안 물어봄.

**비밀번호 입력**: 첫 회는 ssh 비번을 직접 입력. 매번 입력하기 싫으면 ssh-key 등록 (아래 보충).

**전송 확인**: 명령이 끝나면 끝. 진행 표시줄(`100%`)이 끝까지 갔는지만 확인. 서버 측에 ssh 로 들어가 `ls -la /tmp/reportarchive-*.tar.gz` 로 한 번 더 검증해도 됨.

#### scp 가 안 뜰 때 (Windows)

`scp : The term 'scp' is not recognized…` 가 뜨면 OpenSSH Client 가 빠져 있는 것. Windows 10 1809 (2018년) 이상에서는 기본 탑재인데 일부 사내 이미지에선 제거돼 있다.

- 설정 → **앱** → **선택적 기능** → **기능 추가** → `OpenSSH 클라이언트` 설치.
- 또는 [WinSCP](https://winscp.net/) (GUI 도구) 로 같은 작업 가능.

#### 매번 비밀번호 입력이 귀찮을 때 — ssh-key 등록

**윈도우에서 키 생성** (한 번만):
```powershell
ssh-keygen -t ed25519 -C "deploy"
# 경로/패스프레이즈는 그냥 엔터 (기본값)
```
생성물: `%USERPROFILE%\.ssh\id_ed25519` (개인키, 비공개) + `id_ed25519.pub` (공개키).

**공개키를 서버에 등록**:
```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh user@서버IP "cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```
다음 접속부터 scp/ssh 가 비번 안 물어봄.

#### scp 가 막힌 폐쇄망

ssh 자체가 차단된 환경이면:
- **USB 매체**로 옮기기 (tar.gz 한 파일이라 단순함).
- 사내 파일 서버 경유 (FTP/SMB/내부 다운로드 포털 등).
- 운영팀이 정한 반입 절차에 맞춰 처리.

도착지가 `/tmp/<번들이름>.tar.gz` 만 되면 그 다음 단계(A-3)는 동일하게 진행.


### A-5. (선택) nginx HTTPS 운영 — 폐쇄망 / 사설 인증서

설치 직후 앱은 `http://서버IP:3000` 으로 열린다. 여기에 nginx 를 앞단에 세워
`https://서버IP` (443) 로 받게 만드는 절차다.

이 배포는 **백엔드(uvicorn, `127.0.0.1:3000`)가 프론트엔드까지 같이 서빙**하는
통합 배포이므로, nginx 는 정적 파일을 직접 서빙하지 않고 **모든 요청을
`127.0.0.1:3000` 으로 프록시 + TLS 종료만** 하면 된다.
인증은 JWT Bearer 토큰(localStorage) 방식이라 쿠키 Secure 문제도 없어
**백엔드 코드/.env 는 손댈 필요 없다.**

> 아래 `<서버IP>` 는 실제 서버 IP(예: `192.168.10.5`)로 바꿔 입력.

**1) nginx 설치**
```bash
sudo apt install -y nginx
```
> 폐쇄망에 인터넷이 없으면 `apt` 가 실패한다. `prepare` 때 쓴 사내 apt 미러가
> 있거나, 같은 OS 버전에서 `nginx` + 의존 `.deb` 들을 미리 받아 USB 로 들고 와
> `sudo dpkg -i *.deb` 한다.

**2) 사설 인증서 생성 — IP 를 SAN 에 꼭 포함**

내부 IP 로만 접속하므로 인증서 SAN 에 IP 를 넣어야 한다(요즘 브라우저는 CN 만으론
매칭 안 함).
```bash
sudo mkdir -p /etc/nginx/ssl
sudo openssl req -x509 -nodes -newkey rsa:2048 -days 3650 \
  -keyout /etc/nginx/ssl/reportarchive.key \
  -out    /etc/nginx/ssl/reportarchive.crt \
  -subj   "/CN=<서버IP>" \
  -addext "subjectAltName=IP:<서버IP>"
sudo chmod 600 /etc/nginx/ssl/reportarchive.key
```

**3) nginx 설정 배치**

번들 안의 `nginx/reportarchive-ssl.conf.example` 을 쓴다. `<서버IP>` 두 군데를
바꾼 뒤:
```bash
sudo cp nginx/reportarchive-ssl.conf.example /etc/nginx/sites-available/reportarchive
sudo ln -s /etc/nginx/sites-available/reportarchive /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo systemctl enable nginx
```

**4) 백엔드를 외부에 직접 노출하지 않기 (권장)**

기본값(`APP_HOST=0.0.0.0`)이면 `http://서버IP:3000` 으로 HTTPS 우회 접속이 된다.
둘 중 하나로 nginx 만 통하게 막는다.
```bash
# 간단: 방화벽으로 3000 차단 + 443 만 개방
sudo ufw allow 443/tcp
sudo ufw deny  3000/tcp
```
또는 `.env` 에서 `APP_HOST=127.0.0.1` 로 바꾼 뒤
`sudo systemctl restart reportarchive` (nginx 는 localhost 로 프록시하므로 정상).

**5) 확인**

브라우저에서 `https://<서버IP>` 접속. 사설 인증서라 "안전하지 않음" 경고가 한 번
뜨는데(사내용은 정상), "고급 → 계속 진행" 으로 들어가면 끝.

> `client_max_body_size` 는 `.env` 의 `EMBED_MAX_BYTES`(기본 1GB) 이상으로 유지할 것.
> 설정 예시 파일에 `1024m` 으로 잡혀 있다.

## B. 업데이트 (다음 릴리스부터 매번)

### B-1. 개발 컴퓨터

```bash
git add -A && git commit -m "..."
git push

git tag v0.2.0
git push origin v0.2.0
```

### B-2. 중간 윈도우

```powershell
scp $env:USERPROFILE\Downloads\reportarchive-v0.2.0.tar.gz user@서버IP:/tmp/
```

> scp 가 안 깔려있거나 ssh-key 등록이 필요하면 → A-2 절 참고.

### B-3. 운영 서버 — 한 줄

```bash
ssh user@서버IP
tar xzf /tmp/reportarchive-v0.2.0.tar.gz -C /tmp/
cd /tmp/reportarchive-v0.2.0
sudo ./deploy.sh update
```

자동 처리: 서비스 중지 → 이전 SIF를 `app.sif.prev`로 백업 → 새 SIF 배치 → 마이그레이션 → systemd 유닛 재렌더링 → 재시작.

`.env`, DB, uploads는 건드리지 않음.

**롤백**:
```bash
sudo systemctl stop reportarchive
sudo mv /home/<계정>/Projects/ReportArchive/app.sif.prev /home/<계정>/Projects/ReportArchive/app.sif
sudo systemctl start reportarchive
```

## C. 팩토리 리셋 (DB · 업로드 통째로 초기화)

운영 데이터를 통째로 비우고 시드 상태로 되돌리고 싶을 때 (예: AI로 더미 채워진 워크스페이스/보고서 청소).

```bash
ssh user@서버IP
# (선택) 최신 번들이 있으면 같이 풀어서 거기서 실행하면 SIF도 함께 교체됨
tar xzf /tmp/reportarchive-v0.2.0.tar.gz -C /tmp/
cd /tmp/reportarchive-v0.2.0

sudo ./deploy.sh reset
# → "reset" 타이핑으로 확인
```

자동 처리:
- 서비스 중지
- `DROP DATABASE report_automation` → 빈 DB로 다시 생성
- `<INSTALL_DIR>/uploads/*` 삭제
- (번들에 새 `app.sif`이 있으면) SIF 교체
- 마이그레이션 + 시드 재실행
- 재시작

**보존되는 것**: `.env`, Postgres 역할, systemd 유닛, OS 패키지.
**파괴되는 것**: 모든 DB 행, 업로드 파일.

> 데이터가 진짜 중요하면 먼저 백업:
> `sudo -u postgres pg_dump report_automation > ~/pre-reset-$(date +%F).sql`

## D. 한 명령으로 자동 분기

서브커맨드 빼고 그냥:

```bash
sudo ./deploy.sh
```

→ 설치된 흔적이 없으면 `install`, 있으면 `update`. 처음과 두 번째 이후를 신경 안 써도 됨.

## 차이 한눈에 보기

| | 처음 세팅 (A) | 업데이트 (B) | 팩토리 리셋 (C) |
|---|---|---|---|
| 사용 명령 | `prepare` → `install` | `update` | `reset` |
| OS 패키지 | 설치 | 건너뜀 | 건너뜀 |
| DB 사용자/DB | 생성 | 그대로 | 그대로 (행만 비움) |
| `.env` | 자동 생성 | 그대로 | 그대로 |
| systemd 등록 | 렌더링 + enable | 재렌더링 | 재렌더링 |
| 데이터 | 시드만 | 보존 | **파괴 후 시드** |
| 소요 시간 | 10~30분 | ~2분 | ~1분 |

## F. v0.1.x → v0.2.0 마이그레이션 (구 `/opt/reportarchive` 설치본)

기존 v0.1.x는 `/opt/reportarchive/`에 `reportarchive` 시스템 사용자로 설치돼 있다.
v0.2.0부터는 `/home/<계정>/Projects/ReportArchive/`에 운영 계정으로 동작하도록 바뀌었음.
운영 데이터를 보존할 필요 없으면 (현 상황) **클린 마이그레이션**이 가장 깔끔:

```bash
# 1) 구버전 중지·제거
sudo systemctl stop reportarchive
sudo systemctl disable reportarchive
sudo rm /etc/systemd/system/reportarchive.service
sudo systemctl daemon-reload

# 2) 구 설치 디렉터리 제거 (백업 필요하면 사전 tar)
sudo rm -rf /opt/reportarchive

# 3) 구 DB 비우기 — 새 install이 빈 DB를 기대함
sudo -u postgres psql -c "DROP DATABASE IF EXISTS report_automation;"
sudo -u postgres psql -c "DROP USER IF EXISTS reportarchive;"

# 4) 신규 번들 풀고 prepare → install
cd /tmp/reportarchive-v0.2.0
sudo ./deploy.sh prepare
sudo ./deploy.sh install
```

이 시점부터는 위 A~D 흐름이 그대로 적용된다.
